# 日本語Web UI デザインシステム

実プロジェクトの反復フィードバックから確立した規範。装飾を足して良く見せるのではなく、**余白・面・文字の階層**で秩序を作る。色は「意味」にしか使わない。

- ここに書かれた値(色・ms・px)は**実績のある初期値**。ブランドに合わせて値は差し替えてよいが、**役割の割り当ては変えない**。
- 迷ったら「色を足す」ではなく「余白と階層で解く」。
- 何をデフォルトにするか・一括操作・エラー回復などの**体験設計は Skill `ux-design`** を参照(UXの規律は下記どちらのモードでも共通)。

## 起動プロトコル — 最初に逆質問する(必須)

UIの新規設計・リニューアルでこのスキルを使うときは、**作り始める前に**次を選択式で確認する(既にプロジェクト・過去の会話で決まっている項目は聞かない)。

1. **プライマリカラー**: カラーコードまたは色名で指定はあるか?(例: `#0e7490` / 「深めの水色」/「おまかせ」)。おまかせ→既定のネイビー `#1d63be`。指定色が原色・蛍光なら§2-1のトーン調整を提案する。
2. **ロゴ・アイコン素材**: 既存のロゴ/アプリアイコンはあるか? あれば受け取り、①ヘッダー・faviconに使用 ②ロゴから色を抽出してbrand/差し色の候補にする。なければテキストロゴで開始(ロゴの自作はしない)。
3. **デザインモード**(下記から1つ):
   - **A. ミニマル・信頼**(既定) — 業務システム・金融・レポート・管理画面向け。罫線と余白で秩序、地は白〜極薄ティント。本書の基本形。
   - **B. Pop・親しみ** — toC ツール・コンシューマー向け。色の面を大胆に使い、丸く・太く・遊びを1つ入れる。§15参照。
   モードが変わるのは§1(トークンの一部)・§4(面の作り方)・§15だけで、**カラー規律・禁則・数値・アクセシビリティ・UXの規律はモード共通**。

## 0. 8秒でわかる原則

1. **色は3系統だけ** — プライマリ1色 + 差し色1色 + グレースケール。ただし白100%は単調。**プライマリの極薄ティントを「面」として使い、白基調のまま気配を出す**(§2-2)。
2. **背景は白基調。黒背景は絶対に作らない** — ヒーロー/結果カード/パネルを黒地・ダーク地にしない。ダークモードは要件で明示されない限り実装しない(ライト固定)。
3. **メリハリ: 1画面に視覚的主役を1つ** — 全部同じサイズ・太さの画面は視線の行き場がない。「まずここ」を大きく、それ以外は静かに(§3)。
4. **マニュアル不要** — 押せるものは押せる見た目、押せないものに押せる見た目を与えない。初見で最頻タスクが完了できるか(§3-3)。
5. **折返しを設計する** — 単語・数字・チップの「途中折返し」「1文字/1個だけ折返し」を全ブレークポイントで禁止(§5)。
6. **数字はExcel基準でシャープに** — 単位は列ヘッダー、セルは生数値+カンマ。数字は欧文フォントで描画する(§3-2)。
7. **動きは因果の説明だけ** — 装飾のためのアニメーションを足さない。`reduced-motion` で全部止まる。
8. **数字はすべて本物** — 演出のための偽の数字・煽り・偽の緊急性を使わない。

## 1. トークン(役割ベース・テーマ差し替え可能)

```css
:root {
  /* プライマリ: 操作・選択・リンク・進捗(この4用途のみ) */
  --brand: #1d63be;
  --brand-deep: #15498f;
  --brand-soft: #e3edfa;   /* 選択状態・チップ・ヒーロー面のティント */
  --brand-mist: #eef3fa;   /* ページ地(白カードを立たせつつ単調を防ぐ) */

  /* 差し色(補色): 主要CTA + 結果のキー数字(この2用途のみ) */
  --accent: #e8590c;
  --accent-deep: #c74e0b;

  /* テキストと構造(画面の90%はこのグレースケール) */
  --ink: #16191d;          /* 本文 */
  --ink-muted: #545e6b;    /* 補足・ラベル(これより薄い文字を本文に使わない) */
  --line: #e3e6ea;         /* 罫線・境界 */
  --subtle: #f5f6f8;       /* 極薄の面 */

  /* 意味を持つ状態色(彩りではなく機能) */
  --danger: #d93025;       /* エラー・破壊的操作のみ */
  --caution-soft: #fdf6e3; /* 注意の面 */
  --caution-border: #e6c96a;

  /* 数字専用フォント(§3-2) */
  --font-num: "Helvetica Neue", -apple-system, "Segoe UI", Roboto, Arial, sans-serif;
}

body {
  background: var(--brand-mist); /* 60-30-10の「60」。無彩グレーよりbrandの極薄ティント */
  color: var(--ink);
  /* 欧文・数字フォントを先に置き、日本語フォントを後に(数字を和文フォントで描画しない) */
  font-family: "Helvetica Neue", Arial, "Hiragino Kaku Gothic ProN", "Hiragino Sans", "Noto Sans JP", Meiryo, sans-serif;
  font-feature-settings: "palt"; /* 日本語の詰め */
}
```

### 導入手順(Tailwind v4)

1. `globals.css` の先頭に `@import "tailwindcss";`。
2. 上のトークンと §10(モーション)・§11(フォーカス)のCSSをコピー。
3. `@theme inline` でユーティリティに橋渡し:

```css
@theme inline {

  --color-accent: var(--accent); --color-accent-deep: var(--accent-deep);
  --color-ink: var(--ink); --color-ink-muted: var(--ink-muted);
  --color-line: var(--line); --color-subtle: var(--subtle);
  --color-danger: var(--danger); --color-caution-soft: var(--caution-soft); --color-caution-border: var(--caution-border);

```

4. `[hidden] { display: none !important; }` を必ず入れる(`display: flex/grid` のユーティリティが `hidden` 属性を上書きする事故を防ぐ)。

## 2. カラー規律 — プライマリ + 差し色1色 + グレースケール(最重要)

| 比率 | 役割 | 使う色 |
|---|---|---|
| 60% | 地・背景・カード | 白 / **brandの極薄ティント(brand-mist)** / 極薄グレー |
| 30% | 文字・罫線・区切り | ink / line(グレースケール) |
| 10% | 操作と結果 | brand(操作)+ accent(CTAとキー数字だけ) |

- **brand** は「操作・選択状態・リンク・進捗」のみ。装飾に使わない。
- **accent** は「主要CTAボタン + 結果のキー数字の2箇所だけ」。3箇所目が欲しくなったら設計が間違っている。
- **差し色は1色まで**。2色目の差し色を足さない。緑=成功・黄=注意などのステータス色を「彩り」として増やさない。**1画面の色相は3つまで**。
- **黒・ダーク背景のパネルは絶対禁止**。ダークモードはデフォルトで実装しない(要件で明示されたときだけ、両テーマを最初から設計する。自動反転は禁止)。
- **カード左端の色帯(カテゴリ/ステータスのアクセントボーダー・インセットストライプ)は禁止**(発注者フィードバックによる恒久ルール、2026-07)。分類・状態の色はチップ/ドット/進捗バーの塗りで示し、カードの縁には一切色を付けない。
- 状態の塗り分けはバッジの「塗り・罫線・打消し線」の違いで表現し、色相を増やさない(§6)。

### 2-1. ブランドカラー適用(企業カラーを指定されたとき)

**`--brand` にプライマリカラー、`--accent` に補色系の差し色を1色**割り当て、残りはグレースケールのまま。役割の割り当ては変えない。

| プライマリ(指定色) | 差し色の初期候補 | 備考 |
|---|---|---|
| ネイビー・青系(デフォルト) | オレンジ `#e8590c` | 実績のある既定ペア |
| **深めの水色・シアン系**(実案件で頻出) | コーラルオレンジ `#e8590c` / 淡めのローズ `#e57a9e` | 「真っ青」より深めの水色 `#0e7490` 前後がブランド色になりがち |
| 緑・ライトグリーン | ソフトアンバー `#e0973f` | 緑系accentは成功色と衝突するので不可 |
| ティール・青緑 | コーラル `#e8590c` 寄り | |
| 赤・ワインレッド | チャコール+brand側を赤に | 赤×緑の補色ペアは状態色と衝突するため使わない |
| 紫 | ソフトアンバー `#e0973f` | |
| ピンクを差したいとき | 淡めのローズ `#e57a9e` | 鮮ピンク(`#d6336c`級)はきつい |
| オレンジ・暖色 | ネイビー `#1d63be` 系 | brand/accentの役割を逆に持たせない(操作=指定色) |
| 黒・モノクロ指定 | 青 `#1d63be` を操作色に | 「黒がブランド」でも黒背景パネルは作らない |

> **差し色は淡め・柔らかめに倒す**。CTAとキー数字に使う分には柔らかいトーンでも十分立つ。強い彩度の差し色は画面全体をきつくする(青×オレンジ `#e8590c` は実績上OK、それ以外は一段淡く)。

- **原色・蛍光色をそのまま使わない**。はっきりしすぎる色は視覚的にきつい。純青 `#0000ff` ではなく `#1d63be`、純シアンではなく `#0e7490` のように、**彩度を一段落としたトーン**に調整してから採用する。
- 差し色はプライマリと**彩度・明度のトーンを揃える**(片方だけ蛍光にしない)。
- 白文字を載せる色はコントラスト比4.5:1以上を確認する。足りなければ `-deep` 側を濃くする。
- danger(#d93025)はブランドが何色でも変えない(意味色は共通)。
- ブランド色を差し替えたら **soft/mist ティントも同じ色相から作り直す**(青のティントのまま緑ブランドにしない)。

### 2-2. プライマリの「面」 — 白一色の単調を避ける(ただしコンテンツで使い分ける)

白背景基調は守りつつ、プライマリの気配が全くない画面は単調でブランドの体温が伝わらない。**ただし安易に全ページをティントで塗らない。地の色は「その画面の主役」で決める**:

| 画面の主役 | 地の選択 | 理由 |
|---|---|---|
| 数字・表・長時間の作業(業務一覧・帳票・管理画面) | 白〜無彩の極薄グレー | データが主役。地の色は視覚ノイズになる |
| 行動・感情(toCホーム・結果画面・LP・完了画面) | `--brand-mist`(brandの極薄ティント) | 温度と個性が出る。白カードが浮き立つ |
| 1画面の中で混在 | 地は静かに、**主役の面だけ**ティント | 全部塗ると主役が消える |

使ってよい面(モードA):

| 面 | 使う色 | 用途 |
|---|---|---|
| ページ地(toC・結果系のみ) | `--brand-mist` | 白カードを立たせる地 |
| ヒーロー・結果カードの面 | 白→`--brand-soft` の微グラデ or brand-soft単色 | 視覚的主役の面。**1画面1箇所まで** |
| アイコンチップ・番号チップ | brand-soft地 + brand文字/アイコン | 文字だけの並びに視覚のアンカーを作る(§3-1) |
| 選択状態・アクティブタブ | brand-soft地 + brand-deep文字 | 既存ルール通り |

- ティントは**低彩度・高明度に限る**(本文の可読性を落とさない)。彩度の高いbrandベタ塗りの面は操作要素(ボタン・バー)だけ(モードBは§15の基準に従う)。
- accentの「2箇所ルール」・1画面の色相3つルールは**ティントを増やしても不変**。

## 3. タイポグラフィと日本語組版

### 3-1. メリハリ(視覚的主役) — 同格をダイナミックに分ける

**全部同じフォント・太さ・大きさの画面は、どこから見ればいいか分からない。**

- **1画面に視覚的主役を1つ**決める(結果画面=主数字 / 入力画面=ページタイトルと主要CTA / 一覧=要対応の件数など)。主役はサイズ・太さで圧倒的に立たせ、それ以外は静かに保つ。
- **主役と本文のサイズ比は2.5倍以上**(例: 本文14px ↔ 主数字44px)。中途半端な1.2倍差はメリハリではなくノイズ。
- 階層は**サイズと太さの2軸**で最低2段差を付ける(例: 主役 44px/bold → 見出し 13px/bold → 本文 14px/normal → 補足 12px/muted)。
- **同格の要素はサイズを揃える**(並列カードの見出し同士など)。メリハリは「主役を1つ立てる」ことで作る。全要素を少しずつ大きくしない(フォン・レストルフ効果: 目立つのは1つだから目立つ)。
- ファーストビュー(スクロールなし)に「主役 + 次に取るべき行動(主要CTA)」が入るようにレイアウトする。
- **説明で埋めない — ダイナミックに解く(文字文字しい画面の禁止)**。同じサイズの文字がびっしり並んだ画面は読む前に疲れる。説明文を足したくなったら、先にこの順で視覚要素に置き換えられないか試す:
  1. **数字を主役化する**(文で書かず、大きな数字+短いラベル)
  2. **サイズ・太さの差**で構造を見せる(見出し文を長くするのではなく、キーワードを立てる)
  3. **チップ・番号・アイコンチップ**(brand-soft地)で文字列の並びに視覚のアンカーを置く
  4. **面の分割**(カード・ストリップ)で段落の代わりをする
  文字を減らした分だけメリハリは強くなる。§3「補足文の規律」とセットで適用する。

| 用途 | サイズ | 太さ |
|---|---|---|
| ページ主数字(結果)= 主役 | `text-4xl`〜`5xl`(36〜44px) | bold・accent・`--font-num` |
| ページタイトル | `text-lg`〜`xl`(18〜20px) | bold |
| セクション見出し | `text-sm`(13px) | 太字だが小さく静かに |
| 本文 | `text-sm`(14px) | normal |
| 補足・ラベル | 12px(SPは13px推奨)`text-ink-muted` | normal |

> 見出しを「大きく・色付き」で目立たせない。主役は中身(数字・事実)。

### 補足文の規律(小さいグレーの長文を作らない)

「グレー・小さい・長い」の三重苦は読まれない上に見にくい。**文字を小さくして詰め込むのではなく、文字数が少なくて済む構造にする。**

- 補足・説明文は**1行(全角25〜30字)以内**。2行を超えたら文章を削るのではなく置き場所を変える: 例示は placeholder へ / 条件はラベルの語に含める / 詳細は `<details>` の開示へ。
- コピーは**体言止めの短文**でよい(「貼り付けやドラッグ&ドロップでも」)。丁寧語の冗長化(「〜することができます」→「〜できます」)を刈る。
- **最小フォントサイズ 12px**。11px以下の本文・補足を作らない(チップ・キーキャップ等のUI部品ラベルのみ11pxまで許容)。SPでは補足も13pxを推奨。
- 説明が必要になったら、まず「説明なしで分かるUI(§3-3)にできないか」を疑う。placeholder・デフォルト値・ラベルで挙動を予告できれば説明文は要らない。

### 3-2. 数値の表記 — Excel基準・シャープに

**数字を和文フォントで描画するとボサッと見える。数字は必ず欧文フォントで、表記はExcelに貼って通る形を基準にする。**

```css
.num {
  font-family: var(--font-num);          /* Helvetica/SF系。和文フォントに落とさない */
  font-variant-numeric: tabular-nums;    /* 等幅数字 */
  letter-spacing: -0.02em;               /* 本文サイズの数字は詰めてシャープに */
  white-space: nowrap;
}
.num-display { /* 主数字・KPI用 */
  font-family: var(--font-num);
  font-variant-numeric: tabular-nums;
  letter-spacing: -0.015em;              /* 大型数字は詰めすぎない(-0.03emは窮屈。微妙に空ける) */
  font-weight: 700;
}
/* 大型数字の桁区切りは脇役に落とす(数字が主役、カンマは読みの補助) */
.num-sep { font-size: 0.8em; font-weight: 400; }
/* 通貨記号は「単位」扱い: 数字より小さく・微小な間隔を空ける */
.currency { font-size: 62%; font-weight: 600; margin-right: 0.15em; letter-spacing: 0; }
```

- **主数字・KPIなど大型表示のカンマは `<span class="num-sep">,</span>` でサイズを一段下げる**(0.8em+細字)。**透明度では調整しない**(にじんで見える)。テーブルの通常サイズのカンマはそのまま(Excel互換の読み取りが優先)。
- **通貨記号(¥・$)は単位・助数詞と同じ扱い**: 数字=変数、記号=固定ラベル。`<span class="currency">¥</span>` で数字の約62%サイズに落とし、数字との間に `0.15em` の間隔を空けて「どこからが値か」を見分けられるようにする。単位(万円・通・件)も同様に約58%サイズ(`.unit`)。
- 実装はフォーマッタ側で一括置換: `formatted.replace(/,/g, '<span class="num-sep">,</span>')`。

### 値(変数)とラベル(固定)の描き分け — 「濃く太い数字=変わる値」の文法

画面中のどこが**変数(データによって変わる値)**で、どこが固定の飾りかが一目で分かるように、値のスタイルを全画面で統一する:

| 要素 | スタイル |
|---|---|
| 値(変数) | `.num` / bold / `--ink`(主役ならaccent)— 常に画面で最も濃く太い |
| ラベル(固定) | 12〜13px / `--ink-muted` / normal |
| 単位・通貨記号(固定) | 値の58〜62%サイズ / `.unit` `.currency` |

- この組を崩さない(あるカードでは値が細く、別のカードではラベルが太い、を作らない)。ユーザーは数画面で「濃く太い=データ」という文法を学習する。
- 更新され得る値は `tabular-nums` で**桁が変わっても幅が跳ねない**ようにする。
- 値の更新はカウントアップ(rAF)または背景の一瞬のフラッシュ(brand-soft→透明、400ms)で「変わった」ことを伝える(§10)。

- **テーブル/DB系のセルは「生の数値 + 3桁カンマ」のみ**(例: `23,048`)。`Intl.NumberFormat('ja-JP')` で整形。**単位・通貨は列ヘッダーに書く**(「価格(万円)」「金額(円)」「利回り(%)」)。セル内に「2.3億」「9,800万」と単位を混ぜない(**1列1単位**)。
- 桁の圧縮は**列ヘッダーの単位変更**で行う(円→千円→万円→百万円)。セル側で概数に丸めない。
- **ダッシュボードの主数字・KPIは正確な値**を出す(「86通」「18.6%」)。単位・助数詞は数字の50〜60%サイズで小さく添える(`<span class="num-display">86</span><span class="unit">通</span>`)。「約2.3億円」等の概数は本文・補足の文章内でのみ使う。
- 通貨を円単位で出す帳票は `¥12,345,678` 形式(`style: 'currency'`)。
- 数値は右揃え + `.num`。「3億7,116万/円」のような**途中折返しは全幅で禁止**。

### 3-3. アフォーダンス — マニュアルなしで操作が分かる

- **押せるものは押せる見た目**: ボタンは塗りか罫線+動詞ラベル(§6)。リンクはbrand色。クリック可能なカードは全面クリック+hoverで背景変化+右端に開く方向の記号。
- **押せないものに押せる見た目を与えない**: 静的なバッジ・KPIにhover効果や `cursor: pointer` を付けない。
- **アイコン単独のボタンを作らない**(ラベルを併記する)。例外は閉じる「×」など世界共通の慣習だけで、その場合も `aria-label` 必須。
- hoverでしか出ない操作を作らない(タッチデバイスで発見不能)。行アクションは常時表示するか、明示の「…」メニューに入れる。
- 慣習に従う(ヤコブの法則): 検索は上、主要CTAは右下/右上、戻るは左。独自のジェスチャー・独自配置を発明しない。
- **検収基準: 初見のユーザーがマニュアル・説明なしで最頻タスクを完了できるか。**

### 3-4. 折返し・整列の禁則

- 見出しは `text-wrap: balance`。分断しやすい語は文節単位で `<span class="inline-block">評価</span>` にして「評/価」の分割を防ぐ。
- **チップ・ボタン群の「1個だけ折返し(孤児)」禁止**。flex-wrap の成り行きに任せず等幅グリッドで:
  4個=`grid-cols-2 sm:grid-cols-4` / 5個=`grid-cols-3 sm:grid-cols-5` / 6個=`grid-cols-3 sm:grid-cols-6`。2択は `grid-cols-2` で横幅いっぱい等幅(3列に置いて左に寄せない)。
- ラベルは列幅に収まる短さに書き直す(「330㎡以内(約100坪)」→「330㎡以内」、補足は説明文へ)。
- JSX内の改行はスペースになる。日本語の連続文は `{'…'}` で1つの文字列にする。

## 4. レイアウト

- **アプリシェル**: 白地ヘッダー(高さ56〜64px・下罫線 `border-b border-line`)+ 極薄グレー地の main。
- **ヘッダー左のアプリ名はホームへのリンクにする(必須仕様)**。クリックでホーム画面に戻る。アプリ名は「いつ使うか」が分かる名前。ナビは3つまで。
- **コンテンツ幅**: §5のブレークポイント表に従う。
- **面の重ね方**: 極薄グレー地の上に白カード(`bg-white border border-line`)。影に頼らず罫線で分ける。影はモーダル等「浮いている」ことに意味がある要素だけ。
- **角丸**: カード `rounded-xl` / コントロール・小要素 `rounded-md`。用途で固定し混在させない。
- **余白**: カード `p-5` / 行 `px-4 py-3`(詰めても `py-2` まで)。区切りは背景色ではなく `border-b border-line` の細罫線(最終行は `last:border-b-0`)。
- **定義リスト**: `grid grid-cols-[8rem_1fr]` でラベル列を固定幅に。値は左揃えで縦のラインを通す。

## 5. レスポンシブ規律(4段・コードで固定)

**SP / タブレット / PC / ワイドの4幅すべてで「収まり」を実測してから完成とする。**

| 呼称 | 幅 | コンテナ | 検証幅 |
|---|---|---|---|
| SP | 〜639px | 全幅・padding 16〜20px | **375px** |
| タブレット | 640〜1023px | 全幅・padding 24px | **768px** |
| PC | 1024〜1439px | `max-w-5xl`(1024px)中央 | **1280px** |
| ワイド | 1440px〜 | `max-w-6xl`(1152px)中央・**それ以上広げない** | **1600px** |

- ブレークポイントはTailwind既定(`sm:640 / md:768 / lg:1024 / xl:1280`)に合わせ、独自の中途半端な値(560px等)を作らない。
- **ワイドで間延びさせない**: コンテンツ幅は上限で止める。カードを画面幅なりに引き伸ばさない。
- **どの幅でも「1文字だけ改行」「1個だけ折返し」を出さない**(§3-4)。幅を連続的に縮めて確認し、危険な語は文節 `inline-block`・`balance`・ラベル短縮で先に潰す。
- **ページ全体の横スクロール禁止**。はみ出すのは表などのコンテナ内スクロール(`overflow-x-auto`)だけ。
- フォーム・LPは全幅で `max-w-2xl` 中央寄せ。

### 5-1. モバイル情報削減(SPでは「小さくする」のではなく「減らす」)

SPで全情報を縮小して詰め込まない。**第一階層だけ見せて、残りは開かせる**:

1. **テーブル→カード化**: 640px未満では表を「主要3項目(名前・キー数値・状態)」のカードに組み替える。残りの列は詳細画面かカード内の折りたたみへ。横スクロール表のまま放置は最終手段。
2. **折りたたみ(トグル/アコーディオン)**: 根拠・履歴・上級設定などの第2階層は `<details>` で畳む。初期表示は「次の1歩」に必要な情報だけ。
3. **上位N件+すべて見る**: 一覧はSPで上位3〜5件+「すべて見る」。全件をスクロールで流さない。
4. **KPIの絞り込み**: ダッシュボードのKPIはSPでは主要1〜3個。残りは「詳細」へ。
5. ナビ・アクションは親指で届く位置に。タップ領域44px。

具体テクニックの選び方(何を削るか)は Skill `ux-design` §2 の情報設計に従う。

### 5-2. コンテナクエリ第一(部品は「画面幅」ではなく「容器の幅」で切り替える)

**コンポーネントの折返し・列切替・カード化は `@container` で書く。メディアクエリはページ骨格(ナビ・カラム数・コンテナ幅)だけに使う。**

```css
/* 部品を置く容器に宣言(inline-size が基本・最軽量) */
.list-host { container-type: inline-size; }

/* 容器が狭ければテーブル→カード。サイドバー内でもモーダル内でも同じ部品が正しく振る舞う */
@container (max-width: 639px) {
  .table-scroll { display: none; }
  .item-cards { display: block; }
}

/* 容器基準の流体サイズ(cqi = 容器インライン幅の1%) */
.hero-value { font-size: clamp(28px, 9cqi, 44px); }
```

- 利点: 同じ部品をサイドバー/モーダル/2カラム/全幅のどこに置いても崩れない。**文言の差し替え・多言語化で文字量が変わっても容器基準で耐える**。
- 全ブラウザ対応済み(2023年〜)。フォールバック不要。名前付きコンテナ(`container-name`)は入れ子で対象を明示したいときだけ。
- 適用判断: 「この部品は別の場所にも置くか?」→ Yes なら必ずコンテナクエリ。ページ専用の骨格だけメディアクエリ。
- 数字・チップの折返し禁則(§3-4)もコンテナクエリで守る(容器が狭いときにグリッド列数を落とす)。

## 6. コンポーネントカタログ

### ボタン(3階層 + 破壊的)

```html
<!-- 主要CTA(画面に基本1つ。accentはこことキー数字だけ) -->
<button class="pressable rounded-md bg-accent px-5 py-2 text-sm font-semibold text-white hover:bg-accent-deep disabled:opacity-50">送信する</button>
<!-- セカンダリ(操作=brandの罫線ボタン) -->
<button class="pressable rounded-md border border-brand px-4 py-2 text-sm font-semibold text-brand-deep hover:bg-brand-soft disabled:opacity-50">編集する</button>
<!-- 三次(静かな操作) -->
<button class="pressable rounded-md border border-line bg-white px-4 py-2 text-sm text-ink hover:bg-subtle">キャンセル</button>
<!-- 破壊的(通常は罫線。塗りのdangerは最終確認モーダル内だけ) -->
<button class="pressable rounded-md border border-danger px-4 py-2 text-sm font-semibold text-danger hover:bg-red-50">削除する</button>
```

- ラベルは**動詞で終える**(「送信する」「保存する」)。「〜させていただく」禁止。
- 実行中はボタン内で「送信中…」+スピナーに置き換え、**幅を変えずに**二度押しを防ぐ。

### フォーム

```html
<div class="space-y-1.5">
  <label for="email" class="flex items-baseline gap-2 text-xs font-medium text-ink">
    メールアドレス <span class="rounded bg-subtle px-1.5 py-0.5 text-[10px] text-ink-muted">必須</span>
  </label>
  <input id="email" type="email" inputmode="email"
         class="w-full rounded-md border border-line bg-white px-3 py-2 text-sm placeholder:text-ink-muted/60" />
  <p class="text-xs text-ink-muted">提案メールの送信先になります。</p>
  <!-- エラー時: input に border-danger、直下に -->
  <p class="text-xs text-danger">メールアドレスの形式が正しくありません。</p>
</div>
```

- ラベルは**上置き**。placeholder をラベル代わりにしない(例示のみ)。
- エラーは**その項目の直下**に、現象+直し方で表示。送信時は先頭エラーへスクロール。
- 数値は全角→半角を自動正規化・カンマ許容・`inputMode="numeric"`。ユーザーの入力癖に合わせる(直させない)。
- チェックボックス/ラジオはラベル全体をクリック可能に、タップ領域44px。
- disabled で黙らせるより、押させて理由を言う。disabled にするなら理由を近くに表示する。

### ステータスバッジ(色相を増やさず塗り/罫線/打消しで区別)

```html
<span class="inline-flex items-center whitespace-nowrap rounded-full border px-2.5 py-0.5 text-xs font-medium bg-brand-soft text-brand-deep border-transparent">進行中</span>
<span class="... bg-subtle text-ink border-line">成約</span>
<span class="... bg-subtle text-ink-muted border-line line-through decoration-1">売却済</span>
<span class="... bg-white text-ink-muted border-line border-dashed">取下げ</span>
```

### テーブル

- ヘッダー `text-xs text-ink-muted font-medium border-b border-line`、本文 `text-sm`。**単位は列ヘッダーに**(§3-2)。
- **数値列は右揃え + `.num`(生数値+カンマ)**。行は `border-b border-line hover:bg-subtle`、行アクションは右端。
- SPではカード型に組み替える(§5-1)。横スクロール表のままにするなら `overflow-x-auto` のコンテナに入れる(**ページ全体を横スクロールさせない**)。
- 空のときは EmptyState(下記)を表に見せず単体で。

### 選択バー(一括選択の相棒・ux-design §5-1とセット)

リストで1件でも選択されたら、リスト上部(または画面下部固定)に現れるバー:

```html
<div class="flex items-center gap-3 rounded-lg bg-brand-soft px-4 py-2 text-sm" role="status">
  <span class="font-bold text-brand-deep tnum">3件を選択中</span>
  <button class="text-brand-deep underline-offset-2 hover:underline">すべて解除</button>
  <div class="ml-auto"><!-- 主要アクション(選択件数入りラベル: 「3件に送信する」) --></div>
</div>
```

- ヘッダーの全選択チェックボックスと対で使う。絞り込み中は「表示中の◯件を選択」と対象を明示。
- 主要アクションのラベルに**選択件数を含める**(「送信する」ではなく「3件に送信する」)。

### モーダル / トースト

- モーダルは「文脈を離れられない確認」だけに使う。`max-w-md`・白・`rounded-xl`・影あり。ESCで閉じる・フォーカストラップ・開いたら最初のコントロールへ。**破壊的確認は外側クリックで閉じない**。
- トーストは結果通知用。成功は静かに数秒で消える。**エラーは手で消すまで残し、次のアクションを添える**。`aria-live="polite"`。

### 空状態 / スケルトン / 注意の面

```html
<div class="rounded-lg border border-dashed border-line px-6 py-12 text-center">
  <p class="text-sm font-semibold text-ink">まだ登録がありません</p>
  <p class="mt-1 text-sm text-ink-muted">最初の1件を追加すると、ここに一覧が表示されます。</p>
  <div class="mt-4"><!-- 主要アクション --></div>
</div>

<div class="skeleton h-10 w-full"></div>

<div class="rounded-md border border-caution-border bg-caution-soft px-4 py-3 text-xs leading-relaxed">
  この操作は取り消せません。内容をご確認ください。
</div>
```

空状態は「状態の説明 + 次の1歩」を必ずセットで。読み込みはスピナーよりスケルトン(レイアウトが跳ねない)。

## 7. アイコン方針

- 実績あるストロークアイコンセット(Lucide等)を**単色・同一線幅・16/20px**で。多色アイコン・素人っぽい自作SVG・絵文字は禁止。
- **頭文字アイコンの絶対禁止**: 四角や丸に漢字・頭文字1字を入れた「イニシャルアイコン」(「登」「報」等)は、どのモードでも絶対に作らない。
- **ありがちなメタファーアイコンも禁止**: 書類(ファイル)・棒グラフ・歯車のような「それっぽいだけ」の汎用アイコンを機能カードに置かない。アイコンは対象が一意に想起できるものだけ。**迷ったらアイコンなし**(太字タイトル+1行の説明のほうがましである)。
- 番号とタイポグラフィで構成できるなら、アイコン自体を省く。
- アイコン単独ボタンは原則作らない(§3-3)。作る場合は必ず `aria-label`。

## 8. カスタムコントロールの座標系(スライダー等)

**ネイティブ描画に自前の目盛りを「合わせにいく」のは必ずズレる。逆にする:**

- ネイティブ `<input type="range">` は透明化(ghost)して**入力だけ**を担当(ドラッグ・キーボード・タップ・当たり判定)。
- 可視要素(つまみ・塗り・目盛り・ラベル)は**すべて同一の式**から自前描画: `centerX(t) = calc(14px + t × (100% − 28px))`(28px=つまみ径、`box-sizing: border-box` 必須)。
- 検証は自分の式ではなく **DOM実測**(つまみとティックの `getBoundingClientRect` 中心比較)。
- 磁気スナップは目盛り近傍(t差<0.02)で吸着+対応チップ点灯。ただし**既に吸着中の値へは再吸着しない**(キーボード微調整が抜けられなくなる)。
- 離散量子化(例: 200段階)で「カリカリ」した手応えに。対数/平方根スケールで大きな値域をカバー。

## 9. データ表現 — バーチャートは「100%が定義できるとき」だけ

**「何に対する長さなのか」が言えないバーを描かない。**

バーを使ってよい3条件(いずれかを満たすこと):
1. **進捗**: 分母が明示できる(「目標120通に対して86通(72%)」— 100% = 目標)。
2. **構成比**: 合計が100%になる内訳。
3. **同一単位の実数比較**: 0起点で、最大値をデータ中の最大に固定し、軸(またはラベル)で基準を明示。

禁止・注意:
- **比率(%)同士を恣意的な幅で描かない**(反響率11.2%を45%幅のバーで表すのは嘘のスケール)。
- **2〜3値の比較はバーより「数字+差分」が速い**(「先月 11.2% → 今月 18.6%(+7.4pt)」)。バーチャートを使いすぎない。
- 裸の棒禁止: バーには必ずラベルと数値を添える(図形だけで意味を伝えない)。
- 色は現状=グレー、対象=brand。accentをグラフに使わない。
- 円グラフは2分割(残量表現)まで。3分割以上は表にする。

## 10. モーション(控えめ・因果の説明のみ)

すべて `prefers-reduced-motion: reduce` で無効化。装飾のための動きは足さない。

| 用途 | 実装 | 時間 |
|---|---|---|
| 画面/質問の遷移 | 方向つきスライド(`--dir: 1/-1` で進む/戻る) | 出150ms / 入260ms |
| カード・選択肢の入場 | `rise-in`(fade + translateY(10px))+ `--stagger` 40〜70ms刻み | 260ms |
| 選択フィードバック | チェックの `pop-in`(scale 0.4→1) | 180ms |
| 押下 | `.pressable`(`active:scale(0.98)`) | 100ms |
| 進捗・数値 | バーの width transition / カウントアップ(rAF + ease-out) | 300〜900ms |

```css
@keyframes rise-in { from { opacity:0; transform: translateY(10px); } to { opacity:1; transform: translateY(0); } }
.rise-in { animation: rise-in 260ms cubic-bezier(0.2,0,0,1) both; animation-delay: var(--stagger, 0ms); }
@keyframes pop-in { from { opacity:0; transform: scale(0.4); } to { opacity:1; transform: scale(1); } }
.pop-in { animation: pop-in 180ms cubic-bezier(0.2,0,0,1) both; }
.pressable { transition: transform 100ms; }
.pressable:active { transform: scale(0.98); }
@keyframes pulse-soft { 0%,100% { opacity:1; } 50% { opacity:.45; } }
.skeleton { background: var(--subtle); border-radius: 6px; animation: pulse-soft 1.4s ease-in-out infinite; }
@media (prefers-reduced-motion: reduce) {
  .rise-in, .pop-in, .skeleton { animation: none; }
  .pressable, .pressable:active { transition: none; transform: none; }
}
```

選択→自動送りは「ハイライトを一拍(約160ms)見せてから」遷移する。

### 10-1. 操作感の基準(参照実装: catnoseのプロダクト群 — Zenn/しずかなインターネット/Nani翻訳)

装飾ではなく「手に馴染む」ための規律。どのアプリでも同じ基準を適用する。

- **触った要素だけが動く**。画面全体を揺らす・スクロールを奪う・関係ない要素を動かすアニメーションは禁止。
- 反応の速度感: hover変化は即時(100ms以内)・押下は `.pressable`・遷移や入場は150〜260msのease-out短距離。バウンス・オーバーシュートは使わない。
- **説明文よりUIが先に語る**: placeholderで挙動を予告(「好きな言語で入力…」=自動判定を一言も説明せず伝える)。機能紹介は「アイコン+体言止め短文」のカードで、段落文を書かない。
- 主要CTAの状態が文脈を語る: 入力が揃うまでの見た目・実行中の「送信中…」・完了後の結果まで、ボタン1つの状態変化で進行が分かる。
- **キーボードショートカットはキーキャップUIで見せる**:

```css
.kbd {
  display: inline-block;
  border: 1px solid var(--line);
  border-bottom-width: 2px;
  border-radius: 4px;
  background: #fff;
  padding: 0 5px;
  font-size: 11px;
  font-family: var(--font-num);
  color: var(--ink-muted);
  line-height: 1.6;
}
```

ショートカット(⌘+Enter等)はボタンの近くに `<span class="kbd">⌘</span><span class="kbd">Enter</span>` で常時またはhover時に表示し、「知っている人だけの隠し機能」にしない(Nani翻訳が送信ボタン近傍に「⌘ Shift Enter」をキーキャップ表示する方式)。挙動の規律は Skill `ux-design` §4-2「送信トリガ」。

## 11. アクセシビリティ

- **キーボードフォーカスを必ず可視化**:

```css
:where(a, button, input, select, textarea, summary):focus-visible {
  outline: 2px solid var(--brand); outline-offset: 2px; border-radius: 4px;
}
```

- コントラスト: 本文は `--ink`、補足は `--ink-muted` まで。それより薄いグレーを本文に使わない。
- タップ領域は最低44px相当。装飾要素(スケルトン等)は `aria-hidden`。
- 状態を色だけで伝えない(バッジは文字ラベルも持つ)。モーダルはフォーカストラップ、トーストは `aria-live`。

## 12. 結果・レポート画面の情報階層

**白・余白・罫線で階層を作る。カードの色分けに頼らない(主役面のティントだけ例外)。**

1. **主数字(=この画面の視覚的主役)** — 小さいグレーのラベル + 大きな数字(ページで唯一のaccent・`--font-num`)。主役の面には白→brand-softの微グラデを使ってよい(§2-2・1画面1箇所)。
2. **前提ストリップ** — 上下の細罫線だけの3カラム(脇役として静かに)。
3. **事実カード** — ユーザーが次に知りたいこと(実際の額・期限)を白カードで。
4. **比較** — 少数比較は「数字+差分(+7.4pt)」。バーを使うなら§9の3条件を満たすものだけ。
5. **CTA**(accent・全幅)。
6. **根拠の開示**(折りたたみ)+ 免責。

各ブロックは `rise-in` + stagger で上から順に現れる。

## 13. UXライティング

- 比喩・話し言葉・キャッチーな造語を避け、**誰が読んでも同じ意味になる直接表現**。
- 専門用語は生活の言葉に言い換える(内部計算では正確な用語を使う)。
- ボタンは動詞で終える。1文50字以内。「〜させていただく」禁止。
- エラーコピーは「何が起きたか + 次に何をすればいいか」。
- **表示する数字はすべて実際の計算結果**。偽の緊急性・煽り・confirmshaming 禁止。

- [ ] **動的パスを実際に操作して検証したか**: 選択→件数連動 / モーダル開閉(ESC・フォーカス復帰) / 実行中→部分成功→再試行 / 下書き保存→復元→破棄 / Enter・⌘+Enter。静的スクショだけで検収しない。

## 15. モードB「Pop・親しみ」(catnoseプロダクト群の実測・発信から汎用化)

nani.nowの実測と、catnoseの発信(「**誰でも入りやすいカラーは淡い青**」「白とグレーだけと決めて配色」「**10秒かかる作業を2秒にする**」「UIから作り、自分が最初のユーザー」「機能は最小限・不要な機能は負債」)を咀嚼したtoC向けモード。**変わるのは「色のトーン・面・丸み・太さ・かわいさ」。組版禁則・数値・アクセシビリティ・UX規律はモードAと完全共通。**

### 15-1. カラー: パステル変換(Popの心臓部)

**Popモードでは指定されたプライマリカラーをそのまま使わず、パステル(淡色)トーンに変換する。**濃紺・原色をPopに持ち込むと途端に硬くなる。

| 指定 | Pop用パステル(面・CTA) | 文字・リンク用のdeep |
|---|---|---|
| 青・水色 | 淡いスカイ `#8ecdf8` | `#2273b8` |
| 赤 | コーラル `#ffa8a0` | `#c2504a` |
| 緑 | ミント `#9adbb4` | `#2e8f5b` |
| 紫 | ラベンダー `#c3b8f0` | `#6b5bb8` |
| ピンク | ベビーピンク `#f9b8cf` | `#c2537e` |
| 黄・オレンジ | アプリコット `#ffcf9e` | `#c07a2e` |

- 変換ルール: **明度を上げ、彩度は中庸に残す**(白っぽすぎると病院、鮮やかすぎると玩具)。
- **主要CTAは「明るいブライト色+白太字+同色相の淡いリング」**(Nani実測: スカイブルーのピル+白文字+外側に淡水色の縁)。リングは `box-shadow: 0 0 0 5px <soft色>`。ブライト色はパステルより一段鮮やかでよいが原色にはしない。
- **プライマリが背景の要素は白文字・白グリフ**(CTA・チェックON・トグルON)。黒いチェックマークは禁止。ネイティブ `accent-color` は明るいプライマリだと**黒チェックを描いてしまう**ため、チェックボックスは自前描画で白チェックにする:

```css
input[type="checkbox"].pop-check {
  appearance: none; width: 22px; height: 22px; border-radius: 7px;
  border: 2px solid #c9dff5; background: #fff; cursor: pointer;
  display: grid; place-items: center;
}
input[type="checkbox"].pop-check:checked { background: var(--pop-primary); border-color: var(--pop-primary); }
input[type="checkbox"].pop-check:checked::after {
  content: ""; width: 11px; height: 6px; border-radius: 1px;
  border-left: 3px solid #fff; border-bottom: 3px solid #fff;
  transform: rotate(-45deg) translate(0, -2px);
}
```

- チェックボックス・トグル等のコントロールのON色は**ブライト**(deepの濃紺を使わない — 1箇所だけ濃いと浮く)。
- deep側は文字・リンク・線画アイコンにだけ使う(面に使わない)。
- 差し色1・accent2箇所・色相3つの規律は不変。

```css
:root[data-mode="pop"] {
  --pop-primary: #43a4f5;      /* ブライト(CTA・トグルON・強調) */
  --pop-primary-pastel: #8ecdf8; /* パステル(マスコット・面) */
  --pop-primary-soft: #d9edfe; /* 選択状態・チップ・CTAのリング */
  --pop-primary-deep: #2273b8; /* 文字・リンク・アイコン */
  --pop-bg: #eaf5fe;           /* ページ地(プライマリ色相の淡色) */
  --pop-card-radius: 24px;     /* カードは罫線なし+大きな角丸(実測27px) */
  --pop-control-radius: 12px;  /* チップ・入力。主要CTAはピル(999px) */
}
html[data-mode="pop"] body { font-size: 16px; } /* 実測16.7px。ゆとり=親しみ */
```

### 15-2. 「これをすればいいんだ」の構造(分かりやすさが最優先)

Popの本質は丸さではなく**迷いゼロ**。catnoseの「10秒の作業を2秒に」を構造で実現する:

1. **1画面1アクション**: ファーストビュー=一言キャッチ+主役カード+CTA1つ、の縦一直線。並列の選択肢をファーストビューに置かない。
2. **開いた瞬間に価値**: ログイン・設定・説明より先に、触れる主役を置く(Naniは開いた瞬間に入力欄)。試すまでの障壁を最下限に。
3. **最頻タスクの手数を数える**: 主役タスクが2〜3操作で完了するか。しないなら機能を削るか、デフォルトで先回りする(ux-design §1)。
4. 説明文で埋めない: 機能は「ストロークアイコン+体言止め1行」。placeholderとマイクロコピーが挙動を語る。
5. 選択は**チップのぽちぽち**(自由入力より選択)。等幅グリッド・太字・選択状態は `--pop-primary-soft`。

### 15-3. かわいらしさの作り方(Nani実測ディテール・幼くならない範囲で)

| 要素 | 作法 |
|---|---|
| マスコット | **必ず本スキルの `assets/pop-mascot-editable.svg` を使う(自作しない)**。使い方は下記「マスコットの使用ルール」 |
| 見出しの遊び | ヒーロー見出し・ロゴは**黒太字+わずかな傾き**(rotate -1〜-2°、ロゴならitalic)。セクション見出しには**波線の下線**(`text-decoration: underline wavy` をsoft色・offset 6px)。どちらも主役級の見出しだけに |
| 手書き注釈 | **くるっとループする矢印**+短い一言(「ログインなしで試せます」)。注釈ごと1〜2°傾けると手書き感が出る。矢印は下の検証済みSVGを使う(ぐちゃぐちゃな自作曲線にしない) |
| 機能カード | **破線ボーダー**(2px dashed soft色)+太字タイトル+1行説明。ありがちなメタファーアイコン(書類・グラフ)は置かない(§7)。**アイコンなしが基本形** |
| コントロール | セグメント切替(淡グレーのトラックに**白ピルが浮く**)/トグルスイッチ(ON=ブライト色)。**設定・調整ボタンはプライマリの枠線で際立たせる**(どこを触れば調整できるかを迷わせない) |
| 角と影 | 全要素大きめ角丸。影はごく淡く低く(色地が浮かせるので基本不要) |
| 文字 | 操作要素も太字700。マイクロコピーは口語OK(「ぽんと送る」)。ただし1文は短く |
| 遊びの上限 | 傾き・波線・ループ矢印・マスコットの顔 — **1画面2〜3つまで**。絵文字は不可 |
| 完了画面 | ピークエンド: マスコット+ひとこと+次の1歩。かわいさの出しどころはここ |

- Enter送信は既定OFFのまま、**設定トグル「Enterキーで送信」として提供してよい**(Nani踏襲。サブラベルに「Shift+Enterで改行」を添える)。既定の送信は⌘/Ctrl+Enter+ボタン(§10-1)。
- くるっと矢印(検証済み・deep色/2.4px/丸端。矢先は下右向き)。**サイズは26px前後の控えめに**、注釈テキストの中央に置く(viewBoxは描画にぴったり合わせてあるので中央揃えでズレない。拡大して使うとループが主張しすぎる):

```html
<svg width="26" height="26" viewBox="0 0 26 26" fill="none" aria-hidden="true">
  <path d="M16 4.2 a4.2 4.2 0 1 0 -1.5 8.1 C 13.2 15.6 14.6 19.2 18.4 21.6"
        stroke="var(--pop-primary-deep)" stroke-width="2.4" stroke-linecap="round" fill="none"/>
  <path d="M14.4 21.4 L 18.9 22 L 18.1 17.7"
        stroke="var(--pop-primary-deep)" stroke-width="2.4" stroke-linecap="round" stroke-linejoin="round" fill="none"/>
</svg>
```

### 15-4. マスコットの使用ルール(`assets/pop-mascot-editable.svg`)

発注者承認済みのキャラクターアイコン原本。**Popモードのマスコットはこれ一択**(CSSで顔を自作しない・別の絵を描かない)。

- **色替えはコードで行う**: SVG内の `:root` CSS変数を差し替えるだけで再着色できる。
  - `--body-light / --body-main / --body-dark` → **プライマリのブライト3トーン**(main=ブライト、lightは+8%明るく、darkは-8%暗く)
  - `--border-light / --border-mid / --border-dark` → **soft側の淡色3トーン**(リング)
  - 瞳(`--pupil-*`)・白目・ハイライトは**どのブランドでも変えない**
- **2バージョンを使い分ける**:
  - **縁ありバージョン**(原本のまま) — ヒーロー・空状態・完了画面・アプリアイコン/faviconなど「主役として置く」場所
  - **縁なしバージョン**(`#outer-frame` の rect を削除し、viewBoxを本体に合わせてクロップ) — ヘッダーロゴ・フッター・リスト内など「小さく添える」場所。小サイズで縁があると潰れる
- プロジェクトには `mascot-bordered.svg` / `mascot-borderless.svg` の2ファイルとして複製し、`<img>` で使う(サイズは width/height 属性で指定)。
- 表情・目の位置の改変はしない。動かすのは完了画面の一拍(pop-in)だけ。

### Popでも不変の規律(親しみと引き換えにしないもの)

- **視覚的主役は1画面1つ**(§3-1)。丸く・太くしても、全部を目立たせれば視線誘導は死ぬ。
- 数値・単位・カンマの規律(§3-2)、「濃く太い数字=変わる値」の文法、フォーカス可視化・タップ44px(§11)、Enter送信の規律とキーキャップ表示(§10-1)はそのまま。
- 黒背景・黒CTAの禁止、reduced-motion対応も不変。バウンスは使わない。

### 使い分けの目安

- **B(Pop)を選ぶ**: 一般消費者向けツール・学習/翻訳/日常系・若年層・「気軽に触ってほしい」が要件のとき。
- **A(ミニマル)を選ぶ**: 業務・金融・医療・報告/管理系・「間違えないこと」が最優先のとき。
- 迷ったらA。Popは「明るくしたい」程度の動機で選ばない(起動プロトコルの逆質問で確定させる)。
