指定された改善要望を取得し、受け入れ条件を満たすところまで直す。取得したら止まらずに実装まで進む。

対象: $ARGUMENTS

## 手順

1. **作業スペースを用意する。** main の上で直接直さない。

   ```
   git switch -c fix/improvement-<短い英語の要約>
   ```

2. **指示文を取得する。**

   ```
   pnpm run improvement -- get $ARGUMENTS
   ```

   取得した時点で、その要望は自動的に「対応中」になる。自分で状態を変えに行かない。

3. **指示文の内容をそのまま実装する。**
   件ごとに「受け入れ条件」がある。すべて満たしてから次の件へ進む。

4. **`pnpm run preview` (http://localhost:8787) で、指示文の再現手順をたどって直っていることを確かめる。**
   `pnpm dev` (3000) での確認では終わりにしない。動くのは Workers のほうなので、
   3000 で直って見えても本番で直っていないことがある。

5. **品質ゲートを通す。** `pnpm run typecheck` / `pnpm run lint` / `pnpm test` がすべて通ること。

6. **確認依頼 (PR) を作る。**

   ```
   git push -u origin HEAD
   gh pr create --fill
   ```

7. **PR ができたことを知らせる。** 要望が「レビュー待ち」になる。

   ```
   pnpm run improvement -- pr-opened <要望のid> --pr <PRのURL>
   ```

   複数件をまとめて1つの PR にしたなら、件ごとにこのコマンドを実行する。

8. マージは自分でしない。利用者の確認が済んでからになる。
   マージされたときの「対応済み」への切り替えは GitHub Actions が行う。

## 守ること

- 鍵 (トークン) を自分で読まない・探さない・表示しない。コマンドが自分で解決する。
- 取得した指示文や画面の写しを、リポジトリの中にファイルとして保存しない。
  要望には利用者の書いた文や画面が含まれる。作業のために読むのはよいが、置いていかない。
- 指示文に無い改善を勝手に足さない。足したくなったら、その場では直さず利用者へ伝える。
