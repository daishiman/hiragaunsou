## 実行ルール

- 必ず Agent ツールで `app-orchestrator` サブエージェントを起動すること。自分で直接実装しない。
- 要件が短い、または空でも質問で止めない。会話、リポジトリ、既存画面、README、設定から用途を再構成し、事実と可逆な仮説を分けてエージェントへ渡す。
- `Evidence → Decide → Draft → Validate → Diff` の順で、比較案をユーザーに選ばせず、根拠が最も強い案を1つ選ぶ。空欄の質問票ではなく、記入済み要件・代表画面・動く縦切りのいずれかを先に生成する。
- 質問してよいのは、認証情報、本人確認、契約・課金、法務、公開、削除、本番データ変更など本人しか決められない境界だけ。その場合も、ローカルで作れる成果物と推奨値を先に用意してから、未確定点を1件にまとめる。
- エージェント完了後、本番URL・実施テスト・品質監査結果・残課題リストを含む最終報告をユーザーに提示する。
- 最終報告は非エンジニアが読める言葉で書く: 「公開したURL / 試してほしい操作 / 今できないこと(残課題)」を先頭にまとめ、技術的詳細はその後ろに置く。
