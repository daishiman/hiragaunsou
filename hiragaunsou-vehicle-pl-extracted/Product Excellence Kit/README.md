# Product Excellence Kit — ビッグテック水準の体験を再現するためのプロダクト設計層

**Version**: 1.0.0(2026-07-05)
**位置づけ**: AIDD Starter Kit / Field Autopilot Kit が「どう安全に作って届けるか(インフラ・デプロイ・セキュリティ)」を担うのに対し、本kitは「**何を作り、どう感じさせるか(要件・体験・品質)**」を担う。両者を重ねて初めてプロベンダー級になる。

## 品質基準の出典(何を「業界最高水準」と定義したか)

Apple・Netflix・LINE・GO(タクシー)らの公開されている設計思想・ガイドライン・実装から、**再現可能な原則だけ**を抽出した:

| 出典 | 抽出した原則 |
|---|---|
| Apple(HIG) | 明瞭さ・操作への即時フィードバック・**「確認ダイアログより取り消し(Undo)」**・プラットフォーム慣習への追従・細部の一貫性 |
| Netflix | **パフォーマンスは機能ではなくUXそのもの**・選択肢を減らして没入させる・感覚でなく計測で判断する(計測設計を機能と同時に作る) |
| LINE | 片手・親指での完結・文字より状態で伝える・**通知の礼儀**(送る価値のある通知だけ)・親しみのあるトーン |
| GO | **システム状態の徹底的な可視化**(車が近づいてくるのが見える)・不確実性を隠さず予測として見せる(到着◯分)・待ち時間の体感短縮 |

これらは playbooks/02(体験設計)と checklists/ に規範として展開されている。

## ディレクトリ構成と使い方

```
product-excellence-kit/
├── README.md
├── playbooks/        ← Claude Codeが従う実行プロトコル(順に実行)
│   ├── 00-master-flow.md          全体フロー(フェーズゲート制)
│   ├── 01-requirements.md         要件定義:課題→成果→体験→機能の5層分解
│   ├── 02-experience-design.md    体験設計:原則・UX心理学の適用ルール・状態設計
│   ├── 03-feature-decomposition.md 機能分解:ストーリーマップ・縦切り・優先順位
│   ├── 04-build-standards.md      実装標準:トークン・状態・アニメーション・計測
│   └── 05-quality-gates.md        品質ゲート:体験QA・性能・リリース判定
├── templates/        ← 案件ごとに複製して埋める成果物(docs/product/ に保存)
│   ├── T1-requirements.md         要件定義書
│   ├── T2-experience-spec.md      体験設計書
│   ├── T3-feature-map.md          機能分解・実装計画
│   └── T4-release-readiness.md    リリース判定書
└── checklists/       ← ゲート通過時に全項目を機械的に検査
    ├── ux-psychology.md           UX心理学(倫理ガード=ダークパターン禁止込み)
    ├── performance.md             パフォーマンス予算
    ├── accessibility-jp.md        アクセシビリティ+日本市場適合
    └── risk.md                    リスク分散
```

**Claude Codeへの導入**: プロジェクトの CLAUDE.md に次の1行を追加する。
> 新規アプリ・新規機能の要件を受け取ったら、必ず `product-excellence-kit/playbooks/00-master-flow.md` を読み、そのフェーズゲートに従って進行すること。

## 設計思想(3行)

1. **体験の品質は才能ではなく工程で作る。** ゲートを通れば誰(どのセッションのClaude Code)がやっても同じ水準に着地する。
2. **心理学は倫理ガード付きで使う。** ユーザーの目標達成を速くするために使い、引き留め・誤認・搾取には使わない(checklists/ux-psychology.md の禁止リスト)。
3. **測れない品質は品質ではない。** 成功指標・性能予算・計測イベントは機能と同時に設計する(後付けしない)。

## Field Autopilot Kit との接続

非IT現場案件では、T1〜T2の内容を「仕様確認カード」(平易な日本語)に**翻訳して**相手に見せる。内部成果物としてはT1〜T4を常にフル作成する(現場に見せる/見せないと、作る/作らないは別)。
