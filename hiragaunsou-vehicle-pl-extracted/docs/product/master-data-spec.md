# マスタ管理の仕様 (車両マスタ・運転者マスタ・率マスタ)

2026-08-08 時点の実装が実際に何をしているかを書き下したもの。
「月次の取込とマスタは同じことを2回入力させているのでは」という問いに答えられる状態にするのが目的。

入力ファイル全体と収支表51列の対応は `docs/product/data-flow-map.md`。ここはマスタ3つに絞って書く。

## 1. 3つのマスタと元データ

| 画面 | 保存先 | 元データ | 読む場所 |
|---|---|---|---|
| 車両マスタ管理 `/admin/vehicle-master` | `vehicle_master` | 社内Excel「★車両別収支計算用2026年5月.xlsx」 | 収支表シートの「車番」「車種名」「所属」「自賠責」「任意保険」「自動車税」「重量税」「車両リース費」「割賦費」 |
| 運転者マスタ管理 `/admin/driver-master` | `driver_master` | 同じ社内Excel「★車両別収支計算用2026年5月.xlsx」 | 収支表シートの「コード」(社員No)「運転者名」「車番」 |
| 率マスタ設定 `/rate-settings` | `rate_master` | なし (画面で手入力) | ― |

### 運転者マスタの出所が収支表シートである根拠 (実ファイルで確認)

社員No と車番の対応は、社内でこのExcelの収支表シートにしか存在しない。

1. `5給与集計表（日給者）.csv` は59列あるが、**車番を表す列を1つも持たない**。
2. `2026年5月売上モニタリスト.csv` は `運転者コード` と `車両コード` を両方持つが、伝票1明細ごとの実績であって割り当てではない(実測で1人が4車番に出る)。
3. 収支表シートでは 車番 : コード が1対1(1つの社員Noが2車番以上に付く行は0件)。人が決めた割り当てはここにしかない。

`運転者コード`(売上モニタリスト)と `社員No`(給与集計表)は同一の番号体系(氏名一致84名すべてで番号も一致)。
一方**氏名は結合キーに使えない** — 収支表シートには `平⽥佳靖` `⼭﨑彰` のように康熙部首(`⽥` U+2F25 等)混じりの表記が実在し、給与集計表の表記と別文字列になる。社員Noで結ぶ限りこの問題は起きない。

- 列は名前で解決する。列の並びが変わっても、見出しの文字が同じなら読める。
- ファイル名では判定しない(名前は毎月・年度ごとに変わり、年月が入っていないこともある)。
  帳票の種別は列見出しで(`detectFileType.ts`)、対象年月はファイルの中身で判定する(`detectYearMonth.ts`、
  根拠の一覧は data-flow-map.md §6-1)。
- どちらのマスタも CSV でも取り込める(車両=9列、運転者=社員No・氏名・車番の3列、文字コードは cp932)。
  Excel と CSV のどちらかは、拡張子ではなくファイルの中身(先頭バイト)で判定する。
- 対象年月のシートが無い場合、マスタの取込だけは**いちばん新しい月のシートで代用**し、
  どのシートを読んだかを画面に出す。保険・税・リース料は車両ごとの決まった金額、
  社員Noと車番の対応は人事の状態で、どちらも「その月の実績」ではないため。
  月次収支表の取込 (`/import`) はこの代用をしない(指定した月の実績が別の月の数字になると気づけないため)。

## 2. 月次の取込はマスタを更新しない (明文化)

**月次データ取込 (`/import`) は `vehicle_master` / `driver_master` / `rate_master` を一切書き換えない。**
マスタは収支計算の入力であって、出力ではない。

- 運行実績CSVに出ている車番でも、車両マスタに無ければ収支表に行が現れない。
- 給与集計表の社員Noは、運転者マスタで車番に結ばれて初めて人件費として車両に乗る。
- したがって**マスタの登録は月次の取込とは別に、この2画面から行う必要がある**。
  同じExcelを選ぶので二重入力に見えるが、読んでいる列も、書き込む先も別物。

かつては完成済み収支表Excelの取込が車両マスタを自動更新していたが、
「紐付けが通っていなくても表が完成してしまう」ため取りやめている。

なお成果物である「運送収支表 2025-2026 …xlsx」年度ブックは、マスタを含めどの数字の供給元にもしない
(`docs/product/data-flow-map.md` §0)。完成済み収支表の取込口は答え合わせ専用で、
相手は STEP7 の結果である「★車両別収支計算用」の収支表シート。

## 3. 依存関係 (この順にしか進めない)

```
率マスタ設定 ─┐
車両マスタ ───┼→ 月次データ取込 (運行実績・給与・請求) → 収支表の作成 → 収支表の確認・確定
運転者マスタ ─┘
```

- 車両マスタが空 → 収支表は0行。固定費(保険料計・賦課税計・運送費計)がすべて0になる。
- 運転者マスタが空 → 収支表の人件費が全車両0になる(「稼働しているのに給与が0です」と指摘に出る)。
- 率マスタが未設定 → 一般管理費・高速割引・賞与が既定値または0で計算される。
- マスタを直すと、その月の収支表は作り直される(けん引先の変更・率の保存はAPI側で再計算まで行う)。

画面はこの依存を導線で表す: 車両マスタの完了パネル → 運転者マスタ → データ取込。

## 4. 上書きの挙動 (全置換ではない)

両マスタとも**追加と上書きだけを行い、既存の行を消さない**(upsert)。

- 同じ車番 / 同じ社員No の行 → 内容を上書き。
- 初めての車番 / 社員No → 追加。
- 取込ファイルに載っていない既存の行 → **そのまま残る**。
- 削除する画面上の手段は用意していない(業務データは消さずステータスで扱う方針)。
  退職者・売却車両を一覧から消したい要望が出たら、無効化フラグとして作る(残課題)。

運転者マスタの確定時、車番が車両マスタに無い行は**その行だけ取り込まず**、
誰が外れたかを画面に出す。車番を空にして黙って登録すると
「登録したのに給与が乗らない」という一番追いにくい壊れ方になるため。

## 5. 取込の2段階

どちらの画面も「ファイルを選ぶ = 読み取りだけ」で、DBには書かない。
新規◯台・更新◯台・取り込めない行◯件を確認してから、ボタンで確定する。
確定すると監査ログ(誰がいつ何件)が残る。

## 6. 今回検討した改善項目の採否 (2026-08-08)

| 項目 | 採否 | 理由 |
|---|---|---|
| 取込前のプレビュー(新規/更新/エラー件数) | 既にあり・強化 | 元からあった。読み取り元のシート名と、上書きの挙動の説明を追加した |
| 既存データとの差分・上書き挙動の明示 | 採用 | 「全部消えるのでは」という不安が確定ボタンを押せなくする。確認画面に1行で常に出す |
| 取り込めなかった行の可視化 | 採用 | 最優先。従来は失敗が小さな赤文字1行で、0台のまま何も起きていないように見えていた |
| 成功時の「◯台を登録しました(新規◯/更新◯)」 | 採用 | 何が起きたか分からないまま画面が戻るのを防ぐ |
| 空マスタ時の「次に何をすればいいか」導線 | 採用 | 0台/0名のときに、影響(固定費0・人件費0)と次の画面へのリンクを出す |
| 車両マスタと運転者マスタの相互整合チェック | 採用 | 確定前に「車両マスタに無い車番」を一覧で出す。従来は確定した後にしか分からなかった |
| トレーラのけん引先未設定への気づき | 採用 | 一覧の最後まで見ないと気づけなかったので、件数と車番を上に出す |
| マスタ未整備が収支表に与える影響の警告 | 採用 | 空状態パネルの本文として出す(専用の警告画面は作らない) |
| 個別の追加・編集・削除 | 見送り | 元データはExcel1本という運用で、画面で1件ずつ直せると「Excelと画面のどちらが正か」が崩れる。直し方はExcelを直して取り込み直す1本に保つ。削除の要望が出たら無効化フラグとして別途設計する |
| 取込結果の手直し(プレビュー上での編集) | 見送り | 同上。プレビューで直せると、取り込んだ内容とExcelが食い違ったまま確定できてしまう |
| UTF-8のCSV対応 | 見送り(残課題) | CSVはすべて cp932 前提。UTF-8を渡すと見出しが文字化けした状態でエラーになる。Excel直取込を主経路にしたので優先度は下がった |
