# 残課題リスト

初回リリース後に見つかった課題を、業務への影響が大きい順に並べる。
着手するときは項目に「着手中」を付け、完了したら消して git 履歴に残す。

## 高 (業務が止まる・数字が間違う)

### 1. 車両マスタ・運転者マスタが本番で0件

本番D1の `vehicle_master` と `driver_master` が0件のまま。手入力画面の車両一覧も収支表の計算も
車両マスタを起点にしているため、これが埋まるまで収支表は1行も作れない。
2026-05 の `vehicle_pl` 106件は「完成済み収支表Excel」を写したもので、CSVから計算した結果ではない。

→ 管理画面から車両マスタ・運転者マスタを取り込む運用手順を確立する。
   (2026-08-08 の変更で、0件のときは画面が理由と登録導線を出すようになった。数字の是正は未了)
   (2026-08-08 追加: 取込が必ず失敗していた原因を修正した。画面の既定の対象月が当月−2、
    渡されるExcelは前月分までしか無いことがあり、月が合わないと 422 で止まっていた。
    マスタは月ごとの実績ではないため、いちばん新しい月のシートで代用し、
    どのシートを読んだかを画面に出すようにした。仕様は `docs/product/master-data-spec.md`)

### 2. 収支表を作り直しても古い行が残る

`D1VehiclePlRepository.upsertMany` は対象が0行のとき何もせずに戻り、`removeVehicles` も
今回の対象から外れた車両しか消さない。そのため車両マスタが0件でも「作り直す」が成功を返し、
旧Excel由来の106行がそのまま残る。画面側では0台のとき成功として見せないようにしたが、
データ側の掃除は未対応。

### 3. 進捗表示の分母が実データと矛盾する

`getWorkflowProgress` の分母が `vehicle_pl` の件数なので「表は0行なのに106台中0台」と出る。
(`kirinEntered` が `miscOther > 0` を見ていて永久に成立しない件は 2026-08-08 に修正済み。
 キリンの協力金の保存先である `rate_master` を直接見るようにした)

### 3-2. インタンク単価が毎月0円から始まる

`rate_master` の `tankPricePerLiter` はマイグレーションで初期値を入れていないため、新しい月は0円で始まる。
気づかずに保存すると、その月の軽油代が全車両0円のまま収支表が出来上がる。
(2026-08-08 の変更で、0円のときは手入力画面が警告と「前月の単価を使う」ボタンを出すようにした。
 毎月の初期値を前月から自動で引き継ぐ仕組みは未対応)

### 3-3. 本番の Google ログイン設定一式

`docs/product/T4-release-readiness.md` の必須ブロッカー1〜5を参照。
この設定が入るまで本番公開は保留する。

## 中 (手間が増える・間違えやすい)

### 4. 車両マスタに無い車番を仮登録できない

運行実績CSVには車番が出ているのに車両マスタに無い車両は、手入力画面に行が出ない。
「実績に出ている車番をワンクリックで仮登録する」導線があれば、マスタ整備を待たずに進められる。
(いま画面は「N台の車番が記録されています」と件数を出すところまで)

### 5. 手入力の保存が全車両を上書きする

保存時に画面上の全車両分を送るため、2人で分担して入力すると後から保存した側の値で
相手の入力が巻き戻る可能性がある。触った車両だけを送る差分保存にしたい。

### 6. 修繕費だけフォールバックが非対称

タイヤ代と高速料金は未入力なら自動計算に回るが、修繕費は空欄=0円になる。
`repairStandard`(走行距離×単価)を計算しているのに使っていない。揃えるか、揃えない理由を書く。

### 7. 「その他諸経費」に入力欄が無い

`miscOther` は収支表の列としても計算経路としても存在するが、入力する画面が無い。
業務フロー docx にも対応する手順が無いため、そもそも人が入れるべき値なのかを確認する。

### 10. 手入力を保存し直すと「確定済み」が黙って解除される

`D1VehiclePlRepository` は収支表を作り直すときに確定フラグを初期化する。締めたあとに
1台だけ直しても月全体が未確定に戻り、画面には何も出ない。解除するなら理由を画面に出すか、
確定後の修正を別の操作として扱うか、どちらかに決める。
(収支表の画面は 2026-08-08 に、確定済みの月では数字を直せないようにして衝突を避けた。
 手入力画面からの保存は従来どおり確定を解除する)

### 11. 入力中に年月を切り替えると入力が消える

手入力画面は年月をキーに作り直すため、保存前に年月を変えると入力内容が失われる。
STEP4の取込リンクで画面を離れたときも同じ。下書きの自動保存を入れたい。
(収支表の確認画面(集中モード)の入力欄には 2026-08-08 に自動保存を入れた。同じ仕組みを手入力画面にも広げる)

### 12. デジタコの総給油量にインタンク以外が含まれるか未確認

自動計算のもとになる給油量が「インタンクのみ」なのか「外部給油を含む」のかを
業務側に確認できていない。含む場合は二重計上になるため、確認して計算方法を確定させる。

### 24. マスタから車両・運転者を外す手段が無い

両マスタとも取込は追加と上書きだけで、既存の行を消さない(`docs/product/master-data-spec.md` §4)。
売却した車両・退職した運転者を一覧から外したい要望が出たら、削除ではなく無効化フラグとして作る。
いまは車番未割当や原価区分で見分ける運用。

### 26. 運行実績CSVが本社分しか手元に無い

業務フロー docx は「3営業所分すべて取り込む」と書いているが、共有された実データは本社分1ファイルのみ。
津山ほかのファイル名と列構成は未確認で、列は本社と同じ前提で実装している。
実ファイルをもらって確かめる。(`docs/product/data-flow-map.md` §7)

### 27. 燃料費・修繕費・高速料金の原票が自動で読めない

STEP3・5・6 の元データは紙・PDFの請求書と給油機レシートで、CSVが存在しない。
現状は手入力画面が正規の経路。OCRでの自動読取は原票を入手してから検討する。

### 25. CSVがUTF-8だと文字化けして取り込めない

すべてのCSV経路が cp932 前提で読む。UTF-8で書き出したCSVを渡すと、見出しが文字化けした
エラーメッセージ(「遉ｾ蜩｡No」等)になり、原因が読み取れない。
Excelの直接取込を主経路にしたため優先度は下がったが、文字コードの自動判別を入れたい。

## 低 (あると嬉しい)

### 8. 前月の値をコピーして始める

インタンク単価や毎月ほぼ同額の項目は、前月値を初期値にすると入力が減る。

### 9. 画面の網羅的な自動テスト(Playwright)

いまは単体・コンポーネントテストのみ。請求書を上から入力して確定するまでと、
収支表の確認画面を1件ずつ処理して反映するまでを、それぞれ1本通しておきたい。
主要フローが固まってから、壊れたら気づける形で足す。

### 13. 集中モードの中での並べ替え・絞り込み

車両ごと・指摘の種類ごとにまとめて見たい要望が出たら足す。
まずは「要修正 → 要確認 → 参考」の順に1件ずつ通す運用で足りるか確かめる。

### 14. 同じ種類の指摘をまとめて「このままでOK」にする

指摘ごとに判断してほしいため、1件ずつの運用で始める。手間が問題になってから足す。
(収支表の表の上での「この車両の指摘をまとめて確認済みにする」も同じ理由で保留)

### 15. 確認画面から元の伝票を1枚ずつ見る

いまは元になっている数字(合計)まで表示している。伝票そのものの表示は
取込画面の作りに手を入れる必要があるため次回。

### 16. 表の上でセルを直接直す使い方の案内

慣れた方向けにセルの直接編集は残してあるが、初めての方が迷わないよう既定では案内していない。
使う人が増えたら操作説明を用意する。

### 17. セル単位の直しの履歴画面

誰がいつ何を直したかは操作の履歴に残っており追えるので、専用画面は使いたい場面が出てからでよい。

### 18. 複数セルのコピー&貼り付け・範囲選択

1件ずつ直しながら判断する作業なので、まとめて貼る場面がまだ無い。

### 19. 乗務員数・賞与(月額)を収支表の上で直す

収支表に列が無い項目のため、従来どおり車両ごとの詳細画面から直す。

### 20. 表の行の仮想スクロール(見えている行だけ描く)

106台では実測で問題が出ていないため、台数が増えてから。

### 21. 確認済みにするときのメモ入力欄

保存の仕組みは用意済み(APIはメモを受け取れる)。画面に欄を出すのは、
判断理由を残したい要望が出てから。

### 22. AI分析の有効化

収支表の確認作業が固まってからでよい。

### 23. 本番URLでの Core Web Vitals 計測

本番公開後に実施する。

## 作らない判断をしたもの

### 収支表の差分再計算

キリン協力金の按分やトレーラの吸収で1台の直しが他の行に波及するため、
差分計算は表全体と同じ知識が必要になる。作り直しを呼ぶ回数を1回に減らすことで
待ち時間の問題は解けているので、作らない。
