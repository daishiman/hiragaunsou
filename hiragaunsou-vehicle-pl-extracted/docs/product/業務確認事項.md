# 業務側へのおうかがい(3件)

作成日: 2026-08-08 / 回答をお願いしたい方: 月次の収支表を作っている担当の方

このアプリは、いまは下に書いた「前提」で数字を出しています。前提が実際の業務と違っていると、
収支表の金額が実際とズレます。**どれも私たちでは決められない、業務の事実**です。
選択肢に丸を付けるだけで結構です。「分からない」も答えとして有効です(その場合は今の前提のまま続けます)。

回答をいただくまでの間、アプリは**今の前提を画面と計算式の両方に書き出したまま**動きます。
勝手に前提を変えることはしません。

---

## 質問1(最優先)デジタコの「総給油量」に、外部の給油スタンドで入れた分は含まれますか?

**聞きたいこと**
運行実績表(デジタコから出す表)に「総給油量(L)」という列があります。この数字は、
会社の給油機(インタンク)で入れた分だけですか? それとも外に出たときにスタンドで入れた分も足されていますか?

**なぜ聞くか(どの数字が変わるか)**
アプリは燃料の量を「インタンク給油量 + 外部給油量」で足しています。
もし**インタンク給油量の側に外部給油分がすでに含まれている**なら、外部給油分を二重に足していることになり、
**収支表の「燃費(km/ℓ)」が実際より悪い数字**で出ます(外部給油の割合が1割なら燃費も約1割低く出ます)。
軽油代の金額そのものは、インタンク単価×インタンク給油量と外部給油代を別々に計上しているため変わりません。

なお、デジタコの「総給油量」は取り込んではいますが、**今の計算には一切使っていません**。
そのため、この回答で今日の金額が動くわけではなく、「今の数え方で合っているか」の確認になります。

**選択肢**

- A: 総給油量には外部給油も含まれる(インタンクの数字と外部の数字は別々に管理している)
- B: 総給油量はインタンクだけ。外部給油は別に集計している
- C: 分からない / 人によって入れ方が違うかもしれない

**答えごとにアプリがすること**

| 回答 | アプリの対応 |
|---|---|
| A | 今のまま(インタンク + 外部で足す)で正しいので変更なし。画面の説明文だけ「デジタコの総給油量は使っていません」と明記したまま残す |
| B | 今のままで正しい。加えて、デジタコの総給油量と「インタンク+外部」が大きく食い違う月に注意を出せるようにする(入力の取りこぼしに気づける) |
| C | 今のまま動かす。1〜2ヶ月分の実データでデジタコの総給油量と手入力の合計を突き合わせ、こちらから「たぶんこちらです」とご報告する |

## 質問2 修繕費が空欄の月は、本当に「その月は0円」ですか? それとも入れ忘れですか?

**聞きたいこと**
修繕費を1台も入力していない、あるいは一部の車だけ空欄のまま確定している月があります。
その空欄は「その月は修理していないので0円」という意味ですか?

**なぜ聞くか(どの数字が変わるか)**
アプリは空欄を**0円として計算**します。もし入れ忘れなら、その車の
**「修繕費計」「変動費」「車両別の利益」がまるごと修理代の分だけ良く見えます**。
修理は1回で数万〜数十万円になることがあるので、1台の月次利益の判断が変わりうる大きさです。

**いまの区別の状況(ご確認いただきたい点)**
手入力の画面では、確定する直前に「修繕費が未入力の車が◯台あります。0円として確定します」と出します。
ただし**保存したあとは、0円と入力したものと空欄のままだったものが同じ数字になり、区別が付きません**
(保管しているデータの作りがそうなっているためです)。

**選択肢**

- A: 空欄は「その月は修理なし = 0円」で正しい
- B: 入れ忘れがありうる。あとから「これは本当に0円か」を見分けられるようにしてほしい
- C: 分からない

**答えごとにアプリがすること**

| 回答 | アプリの対応 |
|---|---|
| A | 今のまま。確定前の「未入力◯台を0円として確定します」の表示は残す(気づける方が良いため) |
| B | 「0円と入力した」と「まだ入れていない」を別のものとして保管できるようにし、収支表の側にも「未入力」と出す。保管の作り変えが必要なので、回答をいただいてから作業します(残課題リストに登録済み) |
| C | 今のまま。数ヶ月ぶんの実績を見て、空欄の出方から傾向をご報告します |

## 質問3 「その他諸経費」は、人が毎月入れる数字ですか?

**聞きたいこと**
収支表に「その他諸経費」という欄があります。この数字は毎月どこかから書き写しているものですか?
それとも、以前の月次表から引き継がれているだけで、実際にはもう更新していない数字ですか?

**なぜ聞くか(どの数字が変わるか)**
アプリには**その他諸経費の入力欄がありません**。旧Excelの月次収支表から取り込んだ値を、
そのまま毎月引き継いで計算に使っています。つまり、
**毎月変わるはずの数字なら、ずっと古い金額のまま計算し続けている**ことになります。
この欄は「諸経費計」を通じて変動費と車両別の利益に、そのまま金額として乗ります。

**選択肢**

- A: 毎月、請求書などを見て人が入れている数字(入力欄が必要)
- B: 車ごとにほぼ固定の金額で、変わったときだけ直せばよい
- C: もう使っていない欄。0円のままでよい
- D: 分からない

**答えごとにアプリがすること**

| 回答 | アプリの対応 |
|---|---|
| A | 手入力の画面に「その他諸経費」の入力欄を追加する(修繕費と同じ並びに置きます) |
| B | 車両ごとの設定として管理画面に置き、毎月の入力からは外す |
| C | 取り込みも計算も0円に固定し、収支表から欄を落とすか常時0で表示する |
| D | 今のまま(引き継ぎ)で動かし、画面に「前の月から引き継いだ数字です」と表示して分かるようにする |

## この3件を「設定項目」にしなかった理由(開発側の判断記録)

3つとも設定画面のスイッチにすることはできますが、**しませんでした**。

- 正解が分かっていない項目をスイッチにすると、**誰も触れないスイッチ**になります。切り替えた結果どの数字がどう動くのかを
  説明できない状態でスイッチだけ置くのは、暗黙の仮定を隠す場所を増やすだけです。
- 質問1は、どちらの回答でも**今日の計算は変わりません**(総給油量を使っていないため)。スイッチを作る意味がありません。
- 質問2でBの回答が来た場合は、スイッチではなく**データの保管の仕方を変える**必要があります。スイッチでは解決しません。
- 質問3は、回答によって**入力欄を足す/管理画面に移す/欄を消す**のいずれかで、どれもスイッチではなく作りの変更です。

代わりに、**いま何を前提に計算しているかを画面と計算式の両方に書き出しました**。回答が来たらそこを直します。

| 前提の書き出し場所 | 内容 |
|---|---|
| 手入力画面(燃料費のステップ) | 「燃料の量はインタンク給油量 + 外部給油量で足しています。デジタコの総給油量は使っていません」 |
| 手入力画面(確認して確定) | 「修繕費が未入力の車が◯台あります。0円として確定します」/「その他諸経費・備品費・メンテ費には入力欄がありません」 |
| 計算式(`src/domain/rules/vehiclePlCalculation.ts`) | 3ヶ所に「業務側に未確認の前提」としてこの文書への参照付きで明記 |
| 取込(`src/infrastructure/parsers/vehicleOperationParser.ts`) | 総給油量は取り込むが計算に使っていないことを明記 |
