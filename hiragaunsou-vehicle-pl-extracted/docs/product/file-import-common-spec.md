# ファイル取込の共通仕様

ファイルを選ぶ画面すべてに共通するルール。**画面ごとに同じことを書かない。各画面の仕様書はこの文書を参照する。**

対象画面(ファイル選択があるところ全部):

| 画面 | パス | 取り込むもの |
|---|---|---|
| 月次データ取込 | `/import` | 車両別運行実績表・売上モニタリスト・給与集計表・完成済み収支表(照合用) |
| 車両マスタ管理 | `/admin/vehicle-master` | ★車両別収支計算用 の収支表シート(車両9列) |
| 運転者マスタ管理 | `/admin/driver-master` | ★車両別収支計算用 の収支表シート(車番・社員No・氏名) |

率マスタ設定(`/rate-settings`)とデータ整形(`/cleansing`)にファイル選択は無い(前者は手入力、後者は取込済みデータの整形)。ファイル選択を追加するときは、この仕様に従うこと。

---

## 1. 原則: ファイル名は判定の根拠にしない

社内のファイル名は月ごと・年度ごとに変わり、年月が入っていないこともある
(実データの `車両別運行実績表（燃費計算）本社.csv` に年月は無い)。名前を根拠にすると、
**中身が別物の改名ファイルを取り違えて取り込む**。

- **何のファイルか** … 列見出し(CSV)・列構成(Excel)で判定する。→ `src/infrastructure/parsers/detectFileType.ts`
- **何年何月分か** … Excelは帳票見出しの和暦、CSVは日付列の値で判定する。→ `src/infrastructure/parsers/detectYearMonth.ts`
- **同じファイルか** … 中身のハッシュで判定する。ファイル名は参考情報として表示するだけ。→ `src/domain/rules/fileImportCheck.ts`

ファイル名は画面に「名前の例」として出してよいが、**その名前でなければ取り込めない、とは読めない書き方にする**。
各画面の説明は「ファイル名は変わっても構いません。中身で判定します。」で統一する。

## 2. 取込の流れ(全画面共通)

```
ファイルを選ぶ
  ↓
下読み (POST /api/import/detect) … 保存は一切しない
  ├ 何のファイルか / 何年何月分か / 必要な列が揃っているか / 前に取り込んでいないか
  ↓
問題なし → そのまま取り込み、判定内容と根拠を結果に表示する
問題あり → 取込を止めて画面で確認を取る(§3)。利用者の明示的な確定操作があってはじめて取り込む
```

**問題が無いときに確認ボタンを増やさない**のは意図的な設計判断。毎月何度も通る操作に摩擦を足すと確認が形骸化し、
本当に止めたいとき(月違い・種類違い)の確認まで読み飛ばされる。代わりに判定内容は取込後の結果に必ず残し、
誤りに気づいたら「取込データ管理」から取り消せるようにする(可逆な操作は摩擦ゼロ・不可逆な操作だけ摩擦1回)。

## 3. 止めて確認するケースと、画面に出す言葉

文言は**全画面で同じ書式**にする。実装は `src/domain/rules/fileImportCheck.ts` の純関数に集約し、
画面側で文章を組み立てない。見せ方は「エラー(赤)」ではなく**注意の面(caution)で「確認」として**出す。

### 3-1. 種類が違うファイル

| | |
|---|---|
| 見出し | このファイルは「売上モニタリスト」のようです |
| 本文 | この欄は「給与集計表(日給者)」を取り込むところです。売上モニタリストは「STEP2 売上モニタリスト」の欄から取り込んでください。 |
| 操作 | [正しい場所を開く] [やめる] |

判定できなかったときは「このファイルが何の帳票か分かりませんでした」とし、期待している列見出しを添える。

### 3-2. 月が違うファイル

| | |
|---|---|
| 見出し | この取込は何年何月分ですか? |
| 本文 | 選ばれたファイルは2026年4月分ですが、いま作成中なのは2026年5月分です。<br>(判定根拠を1行: 「計上日」の日付2104件のうち2104件が2026年4月でした。) |
| 操作 | 取り込む年月[選択] → [2026年4月分として取り込む] [やめる] |

**勝手にどちらかへ倒さない。** 自動判定できた月を初期値として提示し、違えば選び直せるようにする。

### 3-3. 複数の月が混在している / 年月が判定できない

同じパネルを使い、本文を判定結果に差し替える。

- 混在: 「このファイルには 2026年5月 / 2026年4月 の両方が入っています。いちばん多い2026年5月分を初期値にしました。」
- 判定不能: 「この帳票には日付が書かれていないため、中身から年月を判定できません。」(給与集計表・車両別運行実績表)

### 3-4. 必要な列が足りない

| | |
|---|---|
| 見出し | 必要な列が見つかりませんでした |
| 本文 | 「車番」「社員No」の列が見つかりませんでした。ファイルの見出し行をご確認ください。 |
| 操作 | [やめる](取り込めない。ファイルを直して選び直す) |

足りない列名を必ず**具体的に列挙する**。「形式が不正です」のような書き方はしない。

### 3-5. 重複取込(過去に同じファイルを取り込んでいる)

判定は**2軸**で行う。中身の同一性(内容ハッシュ)が主、ファイル名は参考。名前だけで同一と決めつけない。

| 状況 | 見出し | 既定の操作 |
|---|---|---|
| 中身もファイル名も同じ | このファイルは 8月5日 に取り込み済みです(中身も同じです) | **取り込まない**。[それでも取り込む] は残す |
| 名前は同じ・中身が違う | 同じ名前のファイルを 8月5日 に取り込んでいますが、中身が変わっています(更新版と思われます) | **確認必須**。何が変わったか(件数の増減・対象年月)を要約して見せてから [新しい内容で置き換える] |
| 名前は違う・中身が同じ | 別の名前ですが、8月5日 に取り込んだ「2026年5月売上モニタリスト.csv」と中身が同じです | [それでも取り込む] / [やめる] |

**黙って二重登録も、黙って無視も、黙って上書きもしない。** 特に「名前は同じ・中身が違う」を黙って上書きするのが
いちばん危険なので、必ず確認を挟む。

**照合は同じ画面の記録の中だけで行う。** 社内Excel「★車両別収支計算用」は車両マスタと運転者マスタの
両方で正しく使うファイルなので、画面をまたいで照合すると「取り込み済みです」と誤って止めてしまう。

#### 重複の確認と「入れ直し」の確認が続けて出ることがある

月次データ取込では、上の確認に続けて既存の入れ直し確認(「『◯◯.csv』は既に取り込み済みです。入れ直しますか?」)が
出る場合がある。これは冗長ではなく、**別の問いに答えてもらっている**ため意図的に残す。

1. 1つ目 … 「同じファイルですよ。それでも取り込みますか?」(取込前に中身の照合で分かる)
2. 2つ目 … 「今ある◯月分のデータを消して入れ直しますか?」(何を消すことになるかは取込時にしか分からない)

消える対象(ファイル名・件数・取込日時)が具体的に分かるのは2つ目だけなので、不可逆な削除の確認はそちらに残す。
1つ目の確認では削除を伴わない(入れ直しの判断は2つ目に委ねる)。

## 4. 画面に出さない言葉

専門用語は使わない。左を右に言い換える。

| 使わない | 使う |
|---|---|
| バリデーションエラー / スキーマ不一致 | 必要な列が見つかりませんでした |
| ハッシュ / チェックサム | 中身が同じ / 中身が変わっています |
| 重複キー / ユニーク制約 | すでに取り込み済みです |
| パース失敗 | ファイルを読み取れませんでした |
| ソースタイプ | 帳票の種類 |

## 5. 取込の記録(これが無いと重複判定ができない)

すべての取込で `file_import_log` に1件記録する(テーブル定義は `src/infrastructure/db/schema.ts`)。

| 列 | 内容 |
|---|---|
| `screen` | どの画面から取り込んだか (`import` / `vehicle_master` / `driver_master`) |
| `source_type` | 判定された帳票の種類 |
| `year_month` | 判定・確定した対象年月 (マスタ取込など月に紐づかない場合は null) |
| `file_name` | 選ばれたファイル名(参考情報。判定には使わない) |
| `content_hash` | 中身の SHA-256。**同一判定はこれで行う** |
| `row_count` | 取り込んだ件数(「中身が変わっています」の差分要約に使う) |
| `imported_at` / `imported_by` | いつ・誰が |

この履歴は **「取込データ管理」(`/admin/import-batches`)** の「取り込んだファイルの記録」から確認する。画面は新設しない。

- 記録の各行から **[記録から外す]** ができる。これは**取り込んだデータを消す操作ではなく**、
  「取り込み済み」の目印だけを外す操作(同じファイルをもう一度取り込めるようになる)。画面にもその旨を明記する。
- 同じ画面から月次データの実体(`csv_import_batch` / `raw_ingestion`)を削除したときは、
  対応する記録も自動で消す。**片方だけ残ると「取り込み済みです」と案内されるのに実データが無い**という食い違いが起きる。
- マスタ取込は上書き反映のため実体を取り消せない。記録は残るが、戻したいときはファイルを取り込み直す。

## 6. 実装の置き場所

| 役割 | ファイル |
|---|---|
| 帳票の種類の判定(列見出し) | `src/infrastructure/parsers/detectFileType.ts` |
| 対象年月の判定(中身) | `src/infrastructure/parsers/detectYearMonth.ts` |
| 判定結果 → 画面の言葉(共通文言) | `src/domain/rules/fileImportCheck.ts` |
| 下読みAPI(保存しない) | `app/api/import/detect/route.ts` |
| 必須列の一覧(各パーサの定義を集約) | `src/infrastructure/parsers/requiredHeaders.ts` |
| 中身の指紋(SHA-256) | `src/infrastructure/parsers/contentHash.ts` |
| 取込記録の読み書き | `src/infrastructure/db/D1FileImportLogRepository.ts` |
| マスタ確定時の記録 | `app/_lib/recordFileImport.ts` |
| 共通の確認パネル(UI) | `app/_components/ImportCheckPanel.tsx` |
| 記録の閲覧・取り消し | `app/(app)/admin/import-batches/ImportBatchesManager.tsx` |

関連: 各ファイルの列構成と年月の所在は `docs/product/data-flow-map.md` §6・§6-1。
マスタの出所は `docs/product/master-data-spec.md`。
