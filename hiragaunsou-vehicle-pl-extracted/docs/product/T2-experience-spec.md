# T2 画面体験仕様 — 車両別収支管理システム

本書を、このプロジェクトの全画面に適用する **`ScreenExperienceContract`（画面体験契約）の正本** とする。
`T6-information-architecture.md` は画面の責務・名前・配置・遷移、`docs/design-system.md` は視覚トークンと共通部品、
`T5-grid-inline-review.md` は `/grid` 固有の表と確認ウィザードの判断記録、`design-decisions.md` は前例のない例外と検証証跡を担当する。画面で「誰が何をどう完了するか」は本書を優先し、同じ規範をT5/T6へ重複記載しない。

## ScreenExperienceContract（全画面共通）

### 契約に必ず持つ項目

| 項目 | 必須内容 |
| --- | --- |
| 利用場面 | 誰が、どこで、何を見ながら、どの端末で、1回何件扱うか |
| 利用特性 | 利用頻度 × 習熟度、正確性・速度のどちらを優先するか |
| 主目的 | 「読む / 探す / 比較する / 入力する / 1件判断する / 一括処理する / 監査・出力する」から1つ。副操作を主目的と同じ強さで並べない |
| 情報構造 | 原則3〜4群、群間・群内の優先順位、1画面の視覚的主役1つ。超過時は業務上の理由を記録する |
| raw / display | 人向けに加工する値、加工しない値、正確な原値・原本へ戻る経路 |
| 視覚要素 | ラベル・線・アイコン・画像を使う／使わない理由 |
| 表示形式 | 採用形式、決め手、却下候補と理由。表やカードを先に決めない |
| 状態 | 理想・空・ローディング・部分・エラー・オフライン/低速。権限不足・編集不可の理由も明示 |
| 検証 | 0件 / 1件 / 想定最大件数、4幅、実データ、keyboard / touch、アクセシビリティの証跡 |

### 情報設計の8工程（Step 0〜7）

順序を飛ばさず、設計と見た目を別工程にしない。成果物や機能を削除する手順ではなく、先入観を外して表示上の必要性を再判定する手順である。

0. **利用場面を1文にする** — T1の利用場面を画面単位にし、端末・頻度・件数・習熟・正確性を固定する。
1. **値だけで読む** — 読み取り表示のラベルを一度外した状態で、値の書式と文脈だけで意味が伝わるか見る。フォームのラベルと支援技術用の名前は外さない。
2. **必要な意味だけ補う** — 値だけでは一意にならない項目へ、最短のラベル・単位・状態語を戻す。
3. **原則3〜4群に束ねる** — 同じ判断に使う情報を近づけ、別の判断を離す。超える場合は、分割すると比較・入力・監査が損なわれる理由を記録する。
4. **群間・群内を順位づける** — 最初に見る1つを決め、上・左・大きさ・太さで強弱をつける。
5. **表示用に加工する** — コードを業務語、日時を場面に合う形、数値を単位付きへ変換する。同時に原値への復路を決める。
6. **主目的から器を導く** — 件数・関係・操作を基に表、リスト、カード、ウィザード等を比較し、採用・却下理由を残す。
7. **機能と意味のある装飾を足す** — 既存機能を漏れなく戻し、押せる・選択中・重要・隠れ機能の意味を伝える装飾だけを使う。

### 利用頻度 × 習熟度

| | 習熟度が低い | 習熟度が高い |
| --- | --- | --- |
| 利用頻度が低い | 1判断ずつのウィザード、明示ラベル、文字付き操作。前回を覚えている前提にしない | 要約を先に出し、必要時だけ正確な詳細・監査値へ進める |
| 利用頻度が高い | 位置と手順を固定し、選択肢・視線移動を減らす。進捗と取り消しを常時示す | 高密度表、キーボード、一括操作、固定した列・並びを優先する |

頻度は「月1回だから低い」と機械的に決めない。締め期間中に何十件も連続処理する画面は反復操作として高頻度側で評価する。

### 主目的から表示形式を導く

| 主目的 | 基本となる器 | 条件・例外 |
| --- | --- | --- |
| 読む | リスト、カード、定義表示 | 1件の全項目は定義表示。画像が識別の主役の場合だけグリッドを検討する |
| 探す | 検索・絞り込み付きリストまたは表 | 検索条件、該当件数、解除方法を常に追跡できる。見つけた後の判断は別の主目的として分ける |
| 比較する | 表、正確な数値、条件を満たすチャート | 2〜3値なら大きな数値と差分の方が速い。チャートから正確値へ到達できること |
| 入力する | 単件フォーム、ウィザード、同型多件の表 | 項目や判断に順序があればウィザード。数十件を同じ列で入力するなら表 |
| 1件判断する | ウィザード、判断カード、分割ビュー | 根拠と選択肢を同時に示し、周囲の案件をノイズにしない。進捗と保留・取消を失わせない |
| 一括処理する | 表またはリスト + 選択操作バー | カードでも全選択・選択件数・実行前確認を失わせない |
| 監査・出力する | 正確値の表、台帳、印刷文書 | 相対日時・丸め値だけにせず、対象、出力時点、実行者、原本への経路を残す |

主目的が2つ必要に見える場合は、モードまたは画面を分ける。切替を置く場合も既定の主目的を1つ決める。
T6の23画面はこの7分類のいずれかを画面固有の業務文で具体化し、通常画面の判断を本書へ重複転記しない。

### raw値とdisplay値の往復

- 人が頭の中で行う変換はdisplay値で肩代わりする（状態コード→業務語、金額→3桁区切り+単位、日時→場面に合う表現）。変換処理は共通フォーマッタへ集約する。
- **突合、監査、CSV/Excel出力、入力欄ではraw値の正確性を優先**し、丸め・相対日時だけにしない。
- display値を使う場合も、詳細表示・原本・取込バッチなどraw値へ戻る経路を必ず残す。display値からraw値を推測して復元しない。
- AI・OCR・自動補正の候補は事実と分け、採用前に人が原値と比較できるようにする。

### ラベル・線・アイコン・画像の採否

| 要素 | 使う条件 | 使わない条件 |
| --- | --- | --- |
| ラベル | フォーム、表の列見出し、値だけでは意味が一意でない表示、支援技術用の名前 | 氏名・メール等、書式と配置で一意な読み取り表示に同じ意味を重ねる場合 |
| 線 | 多列の表で行列追跡が必要、状態や操作領域の境界を余白だけでは誤認する場合 | 余白・近接・整列で群が読める場合。格子やゼブラを彩りとして足す場合 |
| アイコン | 確立した操作の認識を速め、文字ラベルまたは `aria-label` と組み合わせる場合 | 意味を説明できない飾り、業務語を置き換えて初見理解を下げる場合 |
| 画像 | 人・車両・原票位置など、画像自体が識別または確認の主役になる場合 | 空白を埋める写真・イラスト。意味のある画像に代替テキストを用意できない場合 |

## S1: 月次データ取込

**契約**

| 項目 | 決定 |
| --- | --- |
| 利用場面 | 作成担当が事務所PCで、月次締めの複数ファイルを元帳票と見比べながらまとめて取り込む。現行対応はCSV/Excelで、PDFはFuture |
| 利用特性・主目的 | 月1回だが締め期間に反復。Excel習熟は高い。主目的は入力、副操作は複数ファイルの一括処理。速度と原本追跡を両立する |
| 情報群・主役 | ①対象月と選択条件 ②選択済みファイルと判定 ③取込結果と次の行動。主役は状態に応じ「ファイルを選ぶ」または「月次収支表を見る」 |
| raw / display | 種別、行数、除外数、要確認数を要約するが、正確なファイル名・取込バッチ・失敗した見出しへ到達できる |
| 視覚要素 | 入力ラベルは残す。ファイル行は薄い線または余白で追跡する。アイコン単独にせず文字を残す。画像は使わない |
| 形式 | **段階フォーム + 縦のファイル一覧**。却下: 51列の表（内容比較が主目的ではない）、カードグリッド（処理順と状態を縦に追いにくい） |

- 入口: ナビゲーションの「データ取込」。認証済みの作成担当・管理者のみ。
- 主操作: 対象年月を選び、CSV/Excelを複数選択する。ファイル種別を利用者に選ばせない。PDFを現行対応として案内・受理しない。
- 処理中: 「内容を判定して取り込んでいます」を表示し、重複送信を不可にする。
- 成功: 各ファイルごとに判定した種別、行数、傭車除外数、要確認数を表示する。完成済みExcelなら「月次収支表を見る」を表示する。
- 失敗: ファイル名ではなく、検出できなかったCSV見出しまたはExcel構成を説明して再選択できる。選択済みの正常ファイルは失わない。
- 空・部分: 未取込では対応形式と次の行動を1つ示す。1ファイルだけでも余白が間延びせず、複数ファイル時と同じ読み順にする。

## S2: 月次収支グリッド

**契約**

| 項目 | 決定 |
| --- | --- |
| 利用場面 | 分析担当が事務所PCで、約106台 × 51項目を原資料・前年値と突合し、指摘を連続して確認・修正する |
| 利用特性・主目的 | 締め期間中は高頻度、高習熟、高正確性。主目的は比較、副操作は入力と一括反映 |
| 情報群・主役 | ①年月・確定・反映状態 ②51列の収支表 ③例外・突合・次の行動。表モードの主役は比較対象、確認モードの主役は現在の1件 |
| raw / display | 数値精度を変えずに3桁区切り・単位・業務語を付ける。丸め表示だけにせず、原値・計算根拠・原本へ戻れる |
| 視覚要素 | ラベルは列見出しに1回。行列追跡の細線は必要だが彩りの格子・ゼブラは使わない。操作は文字を残し、画像は使わない |
| 形式 | **高密度表 + 1件ずつの確認ウィザード**。却下: 全件カード（列比較と一覧性を失う）、ウィザードのみ（熟練者の反復速度を落とす） |

- 対象年月を明示し、51列を横スクロールで表示する。表そのものを悪いものとしてカードへ置換しない。
- 異常・要確認のセルは色だけでなく、区分語・件数・読み上げ名でも示す。数値の自動修正や原本の上書きはしない。
- データなしでは取込画面へのリンクを表示する。1台だけでも同じ列構造を維持し、想定最大件数では固定列・スクロール・操作バーが破綻しないこと。
- 初心者向け確認モードと熟練者向け表モードの条件付き両立、却下案、キーボード規律は `T5-grid-inline-review.md` を判断記録とする。

## S3: 確認ボードとAI分析（次段階）

**契約**

| 項目 | 決定 |
| --- | --- |
| 利用場面 | 分析担当・管理者が月次計算後、0〜数十件の例外を判断し、必要時だけAI説明を作る |
| 利用特性・主目的 | 月次・中〜高習熟。確認は「1件を判断する」、AI分析は「根拠を読んで比較する」をそれぞれ主目的とし、同じ面に同格で置かない |
| 情報群・主役 | ①指摘と区分 ②同車種中央値・先月値・原伝票 ③直す/問題なし/あとで見る。主役は現在の指摘と次の1操作 |
| raw / display | 原数値を引用し、比較用の差分・状態語を追加する。AI文から引用元の正確な数値へ戻れる。推測は事実と分ける |
| 視覚要素 | 区分ラベルは意味が異なるため残す。群は余白中心で分ける。業務判断をアイコンだけで表さず、画像は原票確認に必要な場合だけ使う |
| 形式 | **確認は1件ウィザード/カード、AI分析は要約 + 根拠リスト**。却下: 51列表を初見入口にする、複数カードを同格に並べて進捗を利用者に管理させる |

- 諸口・二重計上候補・欠損・異常値を、車番・根拠・状態とともに表示する。0件では「確認はありません」と次の工程を示す。
- ローディング中は現在の入力を保持し、失敗時は「何が起きたか / データは無事か / 次に何をするか」を示す。
- AI分析は元数値を引用し、修繕費・売上・効率・単価等の要因を説明する。生成中・失敗・利用不可を明示し、最終判断は人が行う。

## 全画面の検収条件

- **件数**: 0件、1件、実運用の想定最大件数で確認する。名称・説明・エラー文が2倍の長さでも主役と操作が崩れないこと。
- **4幅**: 375 / 768 / 1280 / 1600pxで実測する。PCの表をSPで無理に縮小せず、必要なら情報を削減・折りたたむ。表を維持する場合は横スクロール中も現在の行列と戻り方が分かること。
- **keyboard**: Tabだけで主要操作を完了でき、フォーカス順が視覚順と一致し、フォーカスが固定要素の下へ隠れないこと。表固有のEnter / F2 / Esc / 矢印操作はT5に従う。
- **touch**: 主要タップ領域は原則44 CSS px以上、隣接操作を誤タップしない間隔を持つ。hoverだけで現れる必須操作を作らない。
- **アクセシビリティ**: フォームは可視ラベルと名前を関連付ける。状態を色だけで伝えない。表はネイティブの行・列見出し関係を保つ。意味のある画像には代替テキスト、装飾画像には空の代替テキストを設定する。エラーは該当箇所と関連付け、読み上げても次の行動が分かること。
- **raw / display**: 加工表示の全対象で正確な値への復路を確認し、突合・監査・出力・入力欄が丸め値だけになっていないこと。
- **形式の証跡**: 採用形式、却下候補、何が何秒または何操作改善するかを実データの比較で説明できること。説明できない装飾変更は採用しない。

## アクセシビリティ・安心設計

- 本節の規範は「全画面の検収条件」に集約する。内部業務用の高密度表は、S2の利用場面と主目的を満たす場合に限って維持する。
- 青は操作・選択、黄は注意など意味のある状態に限定し、重要な例外は色に加えて文字・件数・形でも示す。
- エラーは入力欄の近くに日本語で示し、入力内容を保持したまま再操作できるようにする。
