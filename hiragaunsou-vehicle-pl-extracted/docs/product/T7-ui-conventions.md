# T7. 画面共通の作法 — 言葉・骨格・器の選び方

作成 2026-08-11。内部23画面、認証・404の2表示画面、`/reset-password`のリダイレクトalias
（合計26 route surface）を1つの設計思想で揃えるための共通方針。

**この文書の位置づけ**

- 「誰が何をするか」は `docs/product/T2-experience-spec.md` が正本。
- 「どの画面をどう並べ、どう名乗るか」は `docs/product/T6-information-architecture.md` が正本。
- 「どう見せるか(色・寸法・部品)」は `docs/design-system.md` が正本。
- **この T7 は上の3つを画面横断で運用するための作法**を定める。用語の統一・レイアウトの骨格・
  「表かカードか定義リストか」の判断基準の3つが本体で、既存3文書と競合したら**上の3つが優先**する。

きっかけは依頼者からの5つの指摘(2026-08-11)。

1. ラベルが実態と合っていない
2. ヘッダー・フッターの構造が画面ごとに違う
3. 見えていてほしい情報がスクロールで消える
4. サイドバーが平坦
5. 何でも表になっている

## 1. 用語統一表(指摘1への回答)

### 1-0. 使い分けの原則

1. **1つの概念に1つの言葉。** 同じものを画面ごとに言い換えない。
2. **収支表の項目名だけは元帳票(Excel)の言い回しを正とする。** 突合するときに原本と画面で
   名前が違うと確認できないため。それ以外の集計・見出し・説明文は業務の話し言葉を使う。
3. **迷ったら短い方。** 「1kmあたり原価」より短く言えるなら短い方を採る。ただし略さないと
   意味が変わる場合(「原価」だけでは何の原価か分からない等)は短くしない。

### 1-1. 言い換えの表

| 概念 | 正とする言い方 | 使わない言い方 | 補足 |
|---|---|---|---|
| 運んで得た収入 | **売上** | 今期売上 / 収入 | 収支表の列見出しだけ元帳票どおり「運送収入」 |
| 収入から費用を引いた残り | **損益** | 収支 / 利益 | 赤字のときだけ「赤字」と呼んでよい |
| 1年分の損益 | **年間損益** | 通期収支 / 年計 | |
| 走った距離 | **走行距離** | 稼働Km / 走行(km) | 単位は列見出しに `(km)` |
| 1kmあたりの費用 | **1kmあたり原価** | 1km原価 / km単価 | |
| 1kmあたりの売上 | **1kmあたり売上** | km単価 | |
| 値が正しいか決める行為 | **判定** | 判断 / 確認 | 対象語で画面を区別する(伝票の判定 / 値の判定) |
| 「このままでよい」と決める | **このままでよい** | 問題なし / OK / 確認しました | |
| 「直しに回す」と決める | **直す** | 修正する / 上書きする / 訂正 | |
| いま決めずに残す | **あとで見る** | 後回し / スキップ / 保留 | |
| 収支表を計算し直す | **収支表を作り直す** | 再計算 / 収支表に反映する / 更新する | |
| 月を締める | **確定する** | 締める / ロックする | 月に対してだけ使う |
| 1件を承認する | **このままでよい** | 確定 / 承認 | 「確定」は月にしか使わない |
| 空欄を0円として保存 | **空欄を0円で保存する** | 確定する | 同上 |
| 記録を消す | **削除する** | 消す / 取り消す | 消した記録は「削除履歴」 |
| このアプリを使う人 | **利用者** | ユーザー | 画面名「利用者の管理」 |
| 車を運転する人 | **運転者** | ドライバー / 乗務員 | |
| 対象の月 | **対象年月** | 年月 / 対象月 | 表示は必ず「2026年8月」形式 |
| 表の行の数 | **件数** | 行数 / レコード数 | |
| 取り込んだファイルの種類 | **帳票の種類** | 帳票種別 / ファイルの種類 | |
| 計算の基準値 | **率マスタ** | 単価マスタ / 料率マスタ / 基準 | 画面名は「率マスタ設定」 |
| AIの提供元 | **プロバイダ** | プロバイダー | 長音は付けない |

### 1-2. 数え方の単位

| 数えるもの | 単位 | 例 |
|---|---|---|
| 車両 | 台 | 106台 |
| 運転者・利用者 | 名 | 12名 |
| 表の行・伝票・取込ファイル | 件 | 340件 |
| トラクタとトレーラの組 | 組 | 5組 |

**同じ操作の中で単位を変えない。**「5件を取り込む」と押した結果が「5台を登録しました」に
なるのは誤り。取り込む対象が車両なら最初から「5台を取り込む」。

### 1-3. 画面に出す値は必ず日本語に訳す

内部で使っている英語のキー(`sales`、`fuelTotal`、`corrected` など)を画面にそのまま出さない。
訳の表は以下の1箇所ずつに置き、画面ごとに書き起こさない。

- 収支表の項目名 → `app/_lib/fieldLabels.ts`
- 赤字の要因分類 → `app/_lib/factorLabels.ts`
- 重大さ(要修正 / 要確認 / 参考) → `app/_lib/severity.ts`
- 取込・利用ログの種類 → `app/_lib/kindLabels.ts`

既知キーは型付きの対応表で網羅し、未知キーは用途に合う「未定義の種類」等へ安全に変換する。
調査に必要なraw値はログへ残してよいが、利用者向け画面へfail-openで返さない。

### 1-4. 括弧

画面名・説明文(`screens.ts`)は**全角括弧**（）。ログイン画面など `screens.ts` の外にある
文章も全角に揃える。半角括弧は文中の英数字を囲うときだけ。

## 2. レイアウトの骨格とスクロール責務(指摘2・3への回答)

### 2-1. スクロールしているのは誰か(先に確定する)

**ページ全体をスクロールしているのは文書(body)そのもの。**
`app/_components/AppShell.tsx` の `<main>` には `overflow` の指定が無く、その祖先にも無い。
サイドバー(`<aside>`)だけが自分の中でスクロールする。

したがって:

- **本文の中に置いた `position: sticky` はページのスクロールに対して正しく効く。**
- ただし**`overflow-x: auto` の箱に入れた表の見出しは、ページのスクロールでは固定できない。**
  横スクロールできる箱を作った時点でその箱がスクロールの担当になり、`sticky` は箱の内側だけを
  見るようになるため。これが「これまで表の見出しが1つも固定できていなかった」原因。
- よって**表の見出しを固定するには、その箱に高さの上限を与えて縦にもスクロールさせる**。
  これが唯一確実に効く方法で、共通部品 `DataTable` の `maxHeight` がこれを担う。

### 2-2. 上から下への積み重ね(全画面共通)

| 段 | 中身 | 位置 | 高さの変数 |
|---|---|---|---|
| 1 | アプリのヘッダー(画面名・対象年月・メニュー) | `sticky top-0` z-30 | `--app-header-h` |
| 2 | 工程の帯(毎月の締めの画面だけ) | `sticky top-[--app-header-h]` z-20 | `--screen-step-header-h` |
| 3 | **絞り込みと件数の帯**(該当画面) | 2の下 z-10 | `--screen-filter-bar-h` |
| 4 | 本文 | 流れる | — |
| 5 | 表の見出し行 | 表の箱の中で `sticky top-0` | — |
| 6 | 主要な操作(保存する・次へ) | `sticky bottom-0` z-20 | `--screen-action-bar-h` |

3段目は`StickyFilterBar`が担当する。工程の帯がある画面では`below="stepHeader"`を必須とし、
工程帯の高さを足した位置へ置く。E2Eは各帯の`top`値だけでなく実矩形同士が重ならないことを検証する。

### 2-3. 固定する情報の選び方

固定するのは「**それが見えないと、いま画面に出ている数字の意味が分からなくなるもの**」だけ。

固定する:
- 対象年月・絞り込み条件(「これは何月の、どの範囲の数字か」)
- 件数(「全部で何件のうち何件を見ているか」)
- 表の列見出し(「この数字は何の列か」)
- 保存・次へ(退避先)

固定しない:
- 画面の説明文、この画面ですること、補足の折りたたみ
- 合計行(表の一番下にあることに意味があるため、`<tfoot>` のまま流す)

### 2-4. フッター

アプリ内の全画面は `AppShell` のフッター(「車両収支管理システム — 平賀運送」)を共有する。
シェルの外にあるログイン画面・見つかりません画面にも同じフッターを出し、`AuthShell`に集約する。
`/reset-password`は表示画面ではなく`/sign-in`へのaliasであり、遷移先の`AuthShell`を共有する。

## 3. サイドバーの構造(指摘4への回答)

サイドバーのグループ分けは **T6 §6 で決定済み**で、この T7 では変更しない。決定内容は以下。

- 業務の5グループ(儲かっているかを見る / 毎月の締め / できあがった収支表 / 計算の基準 /
  直した内容の反映)をサイドバーに、運用・設定の2グループをユーザー名のメニューに置く。
- 折りたたみは**採用しない**。毎月開く画面が2クリック先になるため(T6 §6)。
- 件数バッジは異常の未判定件数だけ。

T7 で足すのは見た目の階層だけ:

1. グループ見出しは本文より小さく、区切り線は見出しの**上**に置く(下ではない)。区切りは
   「ここから話題が変わる」の合図であって、飾りではない。
2. いま開いている画面は、面の色と左の縦線ではなく**面の色だけ**で示す(色帯の禁止・design-system §2)。
3. グループ内の並びは業務の順序どおり。五十音・追加順にしない。

## 4. 表・カード・定義リストの選び方(指摘5への回答)

### 4-1. 判断のたった1つの質問

> **その画面で人がやりたいのは「列をまたいで値を見比べること」か、
> それとも「1件を読んで、それについて判断すること」か。**

| 答え | 使う器 | 理由 |
|---|---|---|
| 見比べたい | **表**(`DataTable`) | 同じ項目が縦に揃うから比較できる。揃わない器では比較できない |
| 1件を読んで判断したい | **定義リスト**(`DefinitionList`) | 項目名と値が対になって読める。横に長い1行を目で追わなくてよい |
| 1件だが、まず結論の数字を見たい | **要約カード**(`StatTile`) | 数字を大きく出し、明細はその下に置く |
| 件数が多く、1件ずつ判断していく | **カード + 1件ずつの操作** | 判断のたびに行が消える運用に表は向かない |

### 4-2. 迷ったときの追加の目安

- **1件あたりの項目が7つを超え、かつ行が3行以下** → 表にしない(定義リスト)。
  横に長く縦に短い表は、目が右に流れるだけで比較になっていない。
- **同じデータをグラフと表で二度出さない。** どちらかが要らない。
  比較したいならグラフ、正確な値が要るなら表。両方要るなら表を折りたたみに入れる。
- **1件を編集するのに表を使わない。** 3列の表で1台の値を直すのは、定義リスト+入力欄で足りる。

### 4-3. 表のままにする画面(全画面の判定)

| 画面 | 主目的 | 器 |
|---|---|---|
| 月次収支表(/grid) | 106台を見比べる | 表(見出し固定・車番固定) |
| 年間推移(/annual) | 月をまたいで見比べる | 表(見出し固定) |
| 赤字分析(/deficit) | 車両を損失順に見比べる | 表 |
| 利用者の管理 / 取込の履歴 / 各マスタ | 行を見比べて直す | 表 |
| 利用状況(/usage) | 利用者別費用とログを見比べる | 主数字 + 内訳表 + 監査表 |
| **車両の詳細(/vehicle/[車番])** | **1台を読んで判断する** | **要約カード + 定義リスト**(表を廃止) |
| 異常の判定 / データ整形 / やること | 1件ずつ判断する | カード |
| 自分の設定 / AIの設定 | 1件を読む・直す | 定義リスト・入力欄 |

### 4-4. 表を使うときに必ずやること

1. **縦に長くなり得る対話型の表は列見出しを固定する**（`DataTable`の`maxHeight`を指定する）。
   数行だけの短表と印刷表は、不要な内部スクロールを作らないため例外とする。
2. **列に優先度を付ける**。狭い画面では優先度の低い列を隠す。隠した列がある表には
   「狭い画面では ○○ を省いています」と1行出す(黙って消さない)。
3. **数字は右揃え・等幅**(`.num`)。単位は列見出しに出し、セルには入れない。
4. **空のときは理由を書く**。「データがありません」で終わらせず、なぜ空で、どこへ行けばよいかを書く。

## 5. 部品を使う(自分で書かない)

以下は共通部品があるので、画面ごとに同じものを書き起こさない。
既存の規律は `docs/design-system-components.md` §11 が正本で、T7 では新設分だけを挙げる。

| やりたいこと | 使う部品 |
|---|---|
| 表を出す(見出し固定・横スクロール・列の優先度・空状態) | `DataTable` |
| 1件の項目名と値を並べる | `DefinitionList` |
| 絞り込み条件と件数を上に固定する | `StickyFilterBar` |
| 状態・重大さの札を出す | `Badge` |
| 話題の変わり目に見出しを置く | `SectionHeading` |
| 素のフォームの入力欄・選択欄 | `FIELD_CLASS` / `InputField` |
| ログイン等シェル外の画面の枠組み | `AuthShell` |

**新しい流派を持ち込まない。** ここに無い見た目が必要になったら、まず既存部品で表せないかを
確かめ、それでも必要なら部品を足してこの表に追記する。画面の中に直接書かない。
