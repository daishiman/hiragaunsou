## 【FORM班】マスタ画面の入力を1つの共通部品にまとめた (2026-08-09)

率マスタ・車両マスタ・運転者マスタ・手入力の「直してまとめて保存する」仕組みを、
`app/_components/editForm/` の1組にまとめた。画面側は**直せる項目を宣言するだけ**でよい:
`const FIELDS: EditableFieldDef<T>[] = [{ field, label, kind, read }]` を書き、
`useEditableRecords({ records, rowKey, fields, submit })` で状態を持ち、表の行に
`<EditableRowCells …/>`、画面の下に `<EditFormActionBar form={form} />` を置く。これだけで
入力欄・変更した欄の色と札・元の値の併記・未保存◯件・変更の取り消し・一部だけ保存できなかった
ときの表示・保存しないまま離れようとしたときの確認が、4画面すべて同じ挙動で付いてくる。
項目を増やすときは宣言に1行足すだけで、画面ごとの作り込みは不要。
判定ルール(何を「変更した」と数えるか)と画面の挙動は
`tests/components/editFormFieldDefs.test.ts` と `tests/components/editFormRecords.test.tsx` で固定してある。

- [UX] 車両マスタは106台×9項目を常に入力欄にしている。台数が増えて表示が重くなったら、
  画面に映っている行だけ入力欄にする(それ以外は文字で出す)方式へ切り替える — いまの台数では実測で問題が出ていないため後回し。
- [機能] 保存の失敗が続いたときの再送・下書きの持ち越しは未対応(打った内容は画面に残るが、閉じると消える) — 発生頻度が低いため後回し。

## 【SIDEBAR班】サイドバーの認知負荷を下げた (2026-08-09)

依頼者の指摘「サイドバーに情報が膨大にありすぎる」「畳んだときの件数は要らない」
「絶対にこの情報がないと分からない、というものだけ出してほしい」への対応。**画面は1つも消していない。**

- **アカウント関係をユーザー名のメニューへ移した** — サイドバー下部のユーザー名を押すと、
  マイページ・利用状況・AI設定・ユーザー管理・取込データ管理・データ設計・自動化方針・ログアウトが開く。
  キーボード(↑↓/Home/End)で選べ、Esc と外側クリックで閉じる。
- **グループの折りたたみを廃止した** — 見出しは押せないラベルになり、業務の画面は常に1クリックで着く。
  代わりに**サイドバーごと隠せる**ようにした(ヘッダの「メニューを隠す」/「メニューを表示」)。
  隠した状態は次に開いたときも保たれる。
- **数字と札を減らした** — 畳んだときの項目数・データ取込の登録台数バッジ・ホームの「まずはここ」・
  フッタの重複リンク3本を削除。残したのはチェックの未判定件数だけ(開かずに「手が残っているか」が
  分かる唯一の数字のため)。

置き場所と表示可否の判断基準は `docs/design-system-components.md` §11-9、経緯と採らなかった案は
`docs/product/T6-information-architecture.md` §6。到達不能な画面が出ないことは
`tests/components/AppShellAccountMenu.test.tsx` が権限ごとに固定している。

- [UX] サイドバーを隠した状態はブラウザごとの保存(この端末だけ)。別のパソコンで開くと表示状態に戻る —
  1人が複数端末で使う運用が出てきたらサーバー保存に変える。
- [UX] アカウントメニューに頭文字での絞り込み(type-ahead)は入れていない — 項目が7件で、↑↓だけで十分届くため。
- [検証] 実機の細い画面での確認は未実施(自動テストと開発機のブラウザのみ) — スマートフォンでの利用要望が出た時点で行う。

## 【SIDEBAR班】画面ごとの幅・ボタンの見せ方をそろえた (2026-08-09)

依頼者の指摘「右側に空白がある。全画面共通でお願いします」「「メニュー」っていうボタンは何ですか。
押しても何も表示されない」「文字とボタンだと分かりにくい。アイコンで表示するなどいい塩梅で整えて」
「他の画面でも共通です」への対応。**画面も機能も1つも消していない。**

- **本文の幅を1箇所に集めた** — `app/_lib/screens.ts` の `width`(wide/narrow)だけで決まり、
  `AppShell` の `<main>` に効く。各ページの `max-w-*` 14箇所を撤去。基準は `docs/design-system-components.md` §11-11。
- **「メニュー」ボタンをアイコンにした** — 元は細い画面でサイドバーを出すためのボタン。
  名詞ラベルだったため「押しても何も出ない」と読まれていた。動作を名前にし(メニューを開く/隠す)、
  ホバーでもキーボードのフォーカスでも同じ説明が出る。形は `app/_components/Icon.tsx` の
  最小セットだけを使う。アイコンにしてよい操作の基準は `docs/design-system-components.md` §11-10。
- **ボタンの見た目を共通クラスに寄せた** — 危険な操作用の `.btn-danger` を追加し、手書きしていた
  削除・凍結・ログアウトを置換。リンクに見えて画面が変わらないボタン(下線)を6箇所なくした。
- **名詞1語のラベルを動詞にした** — 削除→「このユーザーを削除する」、取消→「この招待を取り消す」など。
- **空表示の呼び名をそろえた** — `EmptyState` の行き先名を `screens.ts` から取るようにし、
  「月次データ取込へ」「データ取込へ進む」の書き分けをやめた。自前の空表示2箇所を `EmptyState` に統合。

以上は `tests/lib/contentWidth.test.ts` と `tests/lib/buttonStyle.test.ts` が
`app/(app)` 全体を走査して固定している(1箇所直せば全画面に効く形)。

### 全画面を見て回って見つけたが、今回は直していないもの

今回の指摘と同じ種類(幅・余白、ボタンの見せ方、ラベル)を超える作り替えになるため、見送った。

- [UX] **注意書きの面が共通部品を通っていない箇所が約30ある** — `AlertPanel` があるのに、
  手入力・確認ウィザード・確定バーなどが直接 caution 色を書いており、角丸4種・内側余白4種に割れている。
  `AlertPanel` へ寄せれば全部そろうが、手入力の画面に踏み込むため今回は触っていない。
- [UX] **空表示が4系統ある** — 破線の枠・実線の枠・枠なしの文・表の中のセル。うち7箇所は
  「次に何をすればよいか」が書かれていない(ダッシュボード・年間集計・利用状況・確認の記録など)。
- [UX] **カードの縦の間隔が3種類ある**(16/20/24px)。`space-y` を使う画面と、カードごとに `mt-*` を
  書く画面が混在。ページの一番外側を1つの書き方にそろえると消えるが、全画面の差し替えになる。
- [UX] **「戻る」の言い方と置き場所が5通りある** — 「〜に戻る」「〜へ戻る」「戻る」、見出しの上/右上/本文中。
  `PageHead` に戻り先のスロットを足せば1箇所で決まる。
- [UX] **押せない札と押せる札が同じ形をしている** — 一覧の絞り込み札(押せる)と、状態を示すだけの札
  (押せない)が見分けられない。以前の「押せそうで押せない札」と同じ種類の問題。
- [UX] **手書きのボタンがまだ約20箇所残っている**(確認ウィザード・データ整形・取込フォームなど)。
  今回は危険な操作とリンク見えのものだけを直した。
- [UX] **手入力の下部バーの「戻る」「次へ」が行き先を言っていない** — 入力まわりには触らない約束のため見送り。
- [機能] **表を書き出せる画面と書き出せない画面がある** — CSV書き出しは月次収支表だけにあり、
  赤字の理由・年間集計・車両ごとの明細には無い。機能追加の判断が要るため起票のみ。
- [UX] **確認の記録(印刷)だけが共通のページヘッダを使っていない** — 印刷レイアウトの都合。

## 【UI班】全画面の言葉と並びを1つの作法にそろえた (2026-08-11)

依頼者の指摘5件(①ラベルが実際の画面と合っていない ②画面ごとに上下の作りが違う ③見えていないと
困る情報がスクロールで消える ④サイドバーが平らで探しにくい ⑤何でも表になっている)への対応。
決めた作法は `docs/product/T7-ui-conventions.md`、部品は `docs/design-system-components.md` §11〜13 に登録した。
**画面も機能も1つも消していない。数字の出し方・計算は一切変えていない。**

`/reset-password` はパスワード再設定機能が不採用のため `redirect("/sign-in")` だけの中継で、
画面を持たない。**手つかずではなく対象外**(`app/reset-password/page.tsx` の注記のとおり)。

### 今回できなかった・見送ったもの

- [整理] **使われていないパスワード再設定の画面部品が残っている** —
  `app/reset-password/ResetPasswordForm.tsx` は `/reset-password` が中継だけになった時点から
  どこからも呼ばれていない。消して差し支えないが、消す作業は今回の趣旨(見た目をそろえる)と
  別なので触っていない。着手条件: 使われていないファイルの整理をまとめてやるとき。

- [機能] **赤字の理由の画面で、表の見出しに旧い言い方が残っている** —
  `src/usecase/steps/getDeficitAnalysis.ts` の `extraColumnLabel` が「km単価」「修理費(実費)」など、
  今回そろえた言い方(「1kmあたり売上」「修理費」)と食い違う。画面ではなく計算側のファイルにあり、
  今回の約束(計算まわりに手を入れない)に触れるため見送った。着手条件: 赤字の理由の画面に
  別の用事で手を入れるとき。
- [UX] **表の先頭列(車番)を固定して横スクロールしても見えるようにする** — 年間集計の表で、
  横に動かすと何台目の行か分からなくなる。共通の表部品に「先頭列を貼り付ける」機能が要る。
  着手条件: 実際に「横に動かすと車番が分からない」と言われたとき。
- [UX] **共通部品に足したい細かい機能が5つ** — 空表示のボタンで画面を移らずその場で処理する / 表の
  縦のセル結合 / 折りたたみの見出しに札を出す / 年月選びを一時的に押せなくする / 危険な知らせを
  読み上げソフトに伝える。いずれも今回の画面では回避できたため足していない。
- [機能] **マイページの保存が3回に分かれている** — 表示名・メール通知・パスワードがそれぞれ別に
  保存される。1回で保存する形にするには保存の仕組み側を変える必要があり、今回は表示だけを整えた。
- [機能] **利用状況の「今月」が世界標準時で数えられている** — 日本時間の月初・月末とずれる可能性がある。
  計算の話なので今回は触っていない。着手条件: 月初に数字が合わないと言われたとき。

### 最終レビュー波で完了した見送り項目 (2026-08-11)

- [機能] **利用状況の「今月」が世界標準時で数えられていた** — 解消。
  `getJstCalendarMonth` で日本時間の暦月境界に直し、画面上も「業務の対象年月とは別」と明示した。
- ScreenHeader の常設3行説明カードを廃止し、境界案内 + 工程ナビに縮小した。
- 未知 enum の raw 露出を禁止し、型付きラベル表 + 安全 fallback に統一した。
