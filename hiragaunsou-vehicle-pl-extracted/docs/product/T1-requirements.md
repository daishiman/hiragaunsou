# T1 要件定義 — 車両別収支表の月次自動作成

## 成果と計測

- North Star: 月次の車両別収支表を、元データのファイル取込だけで生成し、車両別に損益・利益率・要確認事項を閲覧できる。
- 基準値: 既存の手作業時間を初回運用時に計測する。
- 3か月目標: 収支表作成に要する実作業時間を70%削減する。入力者がExcelへ転記する工程は0件にする。
- ガードレール: 原本をR2に保存し、D1の計算結果から元ファイル・取込バッチへ追跡できること。属人的な判断を自動削除しないこと。

### UI価値の計測

見た目の好みではなく、利用者が迷わず正確に業務を終えられたかで改善を判定する。計測方法の詳細と画面ごとの受入条件は `T2-experience-spec.md` を正本とする。

| 指標 | 初回の基準値 | 3か月目標 | 計測方法 |
| --- | --- | --- | --- |
| 初見の取込完了率 | 初回運用で計測 | 作成担当が口頭説明なしで90%以上完了 | 対象月選択から取込結果表示までの完了数 / 開始数 |
| 最初の正しい操作までの時間 | 初回運用で計測 | 主要3画面で中央値15秒以内 | 画面表示から最初の有効操作までを計測 |
| 熟練者の確認処理速度 | 現行の表操作を実データで計測 | 30件確認時に現行基準より遅くしない | 同じ指摘セットを表モードと確認モードで完了する時間を比較 |
| 正確な値への追跡率 | 100%を必須基準とする | 100%を維持 | 加工表示した値から原値・原本・取込バッチへ到達できる項目数 / 対象項目数 |
| 重大な誤操作 | 初回運用で計測 | 原本上書き・無断自動補正・意図しない確定が0件 | 監査ログと利用者レビューで確認 |

## To-Beフロー

1. 対象年月を選び、現行対応のCSV/Excelをフォルダからまとめて選択する。PDFはOCR結果確認を含む後続拡張で扱う。
2. CSVは列見出し、Excelは「車番〜損益」の51列で種別を判定する。ファイル名の年月・営業所名には依存しない。
3. 原本をR2へ保存し、取込バッチ・生データ・判定フラグをD1へ保存する。
4. 車番88888は傭車として除外する。諸口と重複候補（10・888・5000番等）は消さずに要確認として残す。
5. 計算済みの51列をD1の月次収支表へ反映し、一覧・年間比較・AI要因分析に供給する。

## 業務ルール

- ITP-WEBServiceV3の車両別運行実績表は3営業所分を取り込む。
- 車楽売上は車番別に集計し、キリンの輸送協力金・経営支援金は24番・300番へ半額ずつ配賦する。
- ACELINK NX-CEの給与集計表（日給者）を人件費の根拠とする。
- 燃料、修繕・タイヤ、高速の請求書はCSV/Excelを先に自動取込し、PDFはOCR取込へ拡張する。
- リース・割賦は車両マスタの変更を月次計算へ反映する。

## 利用者の声を受け取る仕組み (2026-08-15 追記)

公開後の改善は、使っている人が困った瞬間に言えるかどうかで決まる。打ち合わせまで持ち越すと
「何が変だったか」が本人の中でも消えるため、業務画面の上で受け取る。

- 全画面の右下から、開いている画面の写しに描き込んで送れる（`docs/product/T2-experience-spec.md` S4 が正本）。
- 集計の単位は実URLではなく画面パターン。「どの画面が一番困られているか」を件数で言えることを条件とする。
- 読めるのは管理者のみ（`manage_improvements`）。他の人が書いた不満がそのまま載るため、入力担当・経営には開かない。
- 計測: 公開後1か月で、要望が0件のまま終わらないこと。0件なら「送る導線が見えていない」と判断して置き方を見直す。
- 送る人に増やす入力は0とする。直す側が必要とする「どの版で・どのブラウザで・裏で何が落ちていたか」は、
  送信時に自動で集める。取れなかったものは空欄にせず「取得不可」と書く。
- 自動で集めたものからは、パスワード・トークン・Cookie・メール・カード番号・電話番号を保存前に伏せる。
  入力された値そのものは記録しない（操作の足あとは「どの要素を押したか」まで）。この境界は会社境界と同じ扱いとする。
- 直すと決めた要望は、管理者の操作で GitHub Issue として渡せること。条件は「その Issue だけを見て着手できる」。
  利用者の投稿では起票しない（スパムと情報漏えいの経路になる）。1つの要望に Issue は1つとする。

## 非目標・制約

- kintone連携、Webサイトを自動操作してのデータ取得、元データが存在しない値の推測は今回の対象外。
- 2重計上の最終判定と諸口の修正／削除は、根拠を示して人が決定する。
- Excel数式は実行しない。既存完成Excelを取り込む場合は、Excelで計算・保存済みの値を使う。

### 入力形式の current / future 境界

| 境界 | 対応 |
| --- | --- |
| **Current（現行の受入対象）** | 内容判定できるCSVとExcel（`.xlsx`）。取込画面で対応形式として表示し、原本と取込バッチを追跡する |
| **Future（後続拡張）** | 燃料、修繕・タイヤ、高速料金等のPDFをOCRし、抽出結果を人が原本と突合してから確定する |

- PDFを現行対応のように表示しない。PDF選択、OCR、抽出結果確認、原本プレビュー、人による確定が一続きで実装・検証されるまでFutureのままとする。
- OCR結果は推測で欠損を埋めず、値・信頼度・原本上の位置を示す。確定前の値を月次収支へ反映しない。

## 受入条件

- 共有された `★車両別収支計算用2026年5月.xlsx` と `運送収支表 2025-2026 5月更新.xlsx` から、指定月の収支表を抽出できる。
- 51列の車両別収支表をD1へupsertし、再取込時に全項目が更新される。
- 未認証・別Origin・20MB超・不明なファイル形式は拒否される。
- Current/Futureの境界どおり、PDFを現行の対応形式として案内または受理しない。
