# Build app

1. `$build-app` と同じメッセージに書かれた内容をアプリ要件として扱う。
2. 要件が空なら、誰が使うか、何ができるか、公開範囲（社内限定・認証あり・一般公開）の3点だけを確認する。
3. `app_orchestrator` カスタムエージェントへ要件を委譲し、完了まで待つ。カスタムエージェントを利用できないクライアントでは、現在のスレッドで `$app-orchestrator` を使用して同じ手順を完遂する。後者は互換フォールバックであり、手順を省略してよいという意味ではない。
4. 要件が書かれている場合は追加質問で止めず、そのままエージェントへ渡して完遂させる。
5. 最終報告の先頭に、公開したURL、試してほしい操作、今できないこと（残課題）を書く。その後に実施テストと品質監査結果を記載する。非エンジニアが一度で理解できる言葉を使う。
