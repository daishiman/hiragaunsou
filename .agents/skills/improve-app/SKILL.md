# Improve app

1. `$improve-app` と同じメッセージに書かれた内容を今回の改善依頼として扱う。
2. 依頼が短い場合は `docs/product/backlog.md`、Issue、利用ログ、未完フロー、テスト失敗を読み、影響度・頻度・依存・リスクから**最有力の1件**を選ぶ。候補一覧を返して選択待ちにしない。
3. 複数要望は内部で分割・採点し、今回進める縦切り1件を確定する。残りは理由つきで残課題へ置く。
4. `app_orchestrator` カスタムエージェントへ「追加開発モード・成果物先行で進める」と明示して委譲し、完了まで待つ。利用できないクライアントでは、現在のスレッドで `$app-orchestrator` を使用して完遂する。
5. ブランチ作成からpreview/PRまで自律的に進め、依頼者には成果物への差分を求める。公開・マージなど権限境界は既存の承認規律を守る。
6. 最終報告は、今回できるようになったこと、試してほしい操作、採用理由、更新後の残課題、次に自動選定した候補の順で書く。git用語は使わず、`app-orchestrator` の語彙対応表に従う。
